# P14 product cutover and bounded retirement packets

Read this change's design and both delta specs, the [two-cycle evidence schema](02-cycle-schema.md), the [target interface map](../../../../docs/runtime-interface-architecture.md), and accepted F1–F3/P8–P13 ledgers. `tasks.md` alone tracks status. This plan is prospective: none of the runtime cutover, two release cycles or human approval has happened. The controller owns shared Makefile/CI/audit, feature/release manifests, default entry, cutover script and ledger. Worker packets use exclusive files. Every new test must fail behaviorally before the implementation, discover nonzero tests, then pass against the real package. Record exact SHA, source/package/runtime hashes, platform/case coverage, hard errors and full previous-release rollback. Planning validation or a mock self-test is never a release cycle.

## Gate and diagnostic contracts

**1.1 Full prerequisite inventory — controller.** Edit `openspec/changes/godot-default-client-switch/ledger.md` and `testdata/runtime-migration/release/cutover-inventory.json`. Bind accepted F1–F3 and P8–P13 implementation SHAs, per-family F3/G1 descriptors, per-target P13 reports, P12 canonical/approved owner cases, F2 protocol/save identities and whole previous-release backup. Enumerate every executable/loading path and transitive native dependency, including pilot Go core ABI and independent `mornlea_client` renderer ABI v19 consumers. A missing required feature/platform/case or mixed producer makes gate fail. Run `openspec validate --all --strict --no-interactive`, `rustup run 1.97.1 cargo metadata --manifest-path packages/engine/Cargo.toml --no-deps --format-version 1` and `go test ./packages/audit -run 'ReleaseUnit|Godot|Architecture' -count=1`; these inspect artifacts but do not substitute for accepted ledgers.

**1.2 Cutover test seam — controller after 1.1.** Create prospective `packages/engine/crates/mornlea_client_core/tests/product_cutover.rs` with file-per-node modules, register prospective `src/local/setup_diagnostics.rs` in controller-owned `packages/engine/crates/mornlea_client_core/src/local/mod.rs`, and create `scripts/godot/product-cutover-check.sh --self-test`. Pin exact v2 `cycle.json`, sorted release-set hash with distinct target package hashes, per-target platform/case/restore references, per-visual-case reviewed owner decision, SHA/actual-host validation and cross-cycle independence in 02-cycle-schema. The permissive fake intentionally accepts one cycle, a Windows report bound to the macOS package, an unreviewed Godot visual candidate under a legacy canonical owner, reused P12 report and wrong backup for behavioral reds; the strict validator rejects them and greens a complete two-cycle fixture. Run `rustup run 1.97.1 cargo test --manifest-path packages/engine/Cargo.toml -p mornlea_client_core --test product_cutover --locked -- --list`, the full target and `scripts/godot/product-cutover-check.sh --self-test`; require nonzero executed tests. Mock success cannot qualify a real cycle.

**1.3 Audit replacement tests — controller after 1.2; exclusive `packages/audit/godot_entrypoints_test.go`, `godot_project_closure_test.go`, `godot_release_unit_test.go` and associated fixtures.** Add red-first checks that product mode has Rust server/client bridge and embedded Python, no Go session/server runtime or tooling CLI, one world writer, native diagnostics and exact platform closure; pilot mode still satisfies its pre-cutover optional constraints. Keep unrelated authority, isolation and visual-owner checks. Run `go test ./packages/audit -run 'Godot|Architecture|ReleaseUnit' -count=1`. Do not delete tests or set exemption variables to make a new entry green.

**2.1 Native pre-import setup diagnostics — worker after 1.2 owns `packages/engine/crates/mornlea_client_core/src/local/setup_diagnostics.rs`, `packages/engine/crates/mornlea_client_core/tests/product_cutover/diagnostics.rs`, `apps/mornlea-godot/app/host/native_setup_diagnostics.py` and `apps/mornlea-godot/tests/scripts/native_setup_check.py`; after P13 launcher accepted.** The Rust probe runs in the native launcher **before loading embedded Python or importing any feature**, checks required server/client/bridge/Python binaries and hashes, target architecture, export/source preparation and manifest identity, and returns a typed `Ready|UnpreparedSource|Missing|Corrupt|WrongArchitecture|MixedRuntime` status. The Python file only displays that status after Python is available; it cannot diagnose a missing Python runtime itself. The controller wires the probe into `packages/engine/crates/mornlea_client_core/src/bin/mornlea-desktop-launcher.rs` in serial 2.2b before either candidate cycle; 3.1 later selects that qualified entry as default. Test unprepared source tree, prepared source, exported package, missing Python interpreter, missing extension, wrong architecture, corrupt bridge, mixed Go/Rust library and repeated teardown with the Rust test and Python display test. Run `rustup run 1.97.1 cargo test --manifest-path packages/engine/Cargo.toml -p mornlea_client_core --test product_cutover --locked diagnostics`, `python3 apps/mornlea-godot/tests/scripts/native_setup_check.py`, `make godot-project-check`. No foreground client.

**2.2 Transitive closure checker — worker after 1.2 owns `scripts/godot/release_closure_check.py`, `packages/engine/crates/mornlea_client_core/tests/product_cutover/closure.rs`; read P13 release manifest.** Walk actual executable/native dependency graph and selected product package, reject pilot Go shared library, Go server process, old renderer ABI consumer, comparison/capture tooling, system Python and non-target libraries; allow specifically inventoried offline tools outside product package and complete previous release. Test direct and transitive Go edge, two distinct ABI surfaces, symlink escape, missing required dependency, partial restore and valid product closure. Run Rust closure filter and `scripts/godot/product-cutover-check.sh --self-test`. This worker does not delete source packages.

**2.3a Release cycle 1 build — controller after accepted1.3/2.2b and P13 target qualification.** Build a complete candidate from one clean committed SHA with a new `release_id` and `build_run_id`; record each target package/manifest/closure/native runtime hash and the sorted release-set digest and expected target/case-set digests in `build/release-evidence/cycle-1`. Run `scripts/godot/desktop-release-check.sh --self-test` only as a harness check, then the actual target builds on their supported hosts. Missing required artifact or dirty source keeps this node open; no default switch.

**2.3b Release cycle 1 full tests — controller after 2.3a.** Run every real P8–P13 semantic, visual, rollback, local/remote and hard-error gate against cycle-1 target package set A on actual macOS/Windows/Linux target hosts. Store typed platform and P12 feature-case reports with cycle-1 release/build/test IDs and each report's matching target package hash and file hashes; require per-case P12 Godot handoff approval or explicit cutover approval for retained legacy visual ownership. Reject one missing/unreviewed required case or wrong host. Run `scripts/godot/product-cutover-check.sh --run-dir build/release-evidence/cycle-1 --strict --validate-reports` plus `make dev-check` and `make test-race`. This does not yet seal a cycle.

**2.3c Release cycle 1 restore and seal — controller after 2.3b.** Stop the candidate writer, restore the complete previous release against the named compatible backup/world snapshot, run its startup/save check, and write the typed restore report. Seal `cycle.json` only after v2 validation recomputes every reference hash and verifies zero hard errors. Run `scripts/godot/product-cutover-check.sh --run-dir build/release-evidence/cycle-1 --strict`, `make dev-check`, `make test-race`. Record seal digest and exact prior-release restore identities. No default switch.

**2.4a Release cycle 2 build — controller only after sealed 2.3c.** Build a subsequent distinct target package set B from a clean committed input; assign new release/build IDs, new target package hashes and a different release-set digest, writing `build/release-evidence/cycle-2`. A repackaged copy of A or borrowed target result fails. Run actual target build commands defined in P13 3.1–3.3 and verify package/manifest/closure/native runtime hashes. No default switch.

**2.4b Release cycle 2 full tests — controller after 2.4a.** Repeat every real P8–P13 semantic, visual, rollback, local/remote, platform and hard-error gate against target package set B, with **new** test/P12 run IDs and target/case reports bound to their matching B target package. Run `scripts/godot/product-cutover-check.sh --run-dir build/release-evidence/cycle-2 --previous-cycle build/release-evidence/cycle-1 --strict --validate-reports`, `make dev-check`, `make test-race`. Reject reused platform/visual/hard-error report even if its content otherwise passes.

**2.4c Release cycle 2 restore and seal — controller after 2.4b.** Stop each B target writer, restore and test the complete named previous release/world/backup again, then seal the v2 report. Recompute hashes and require different release/build/test/release-set/target-package/P12/restore identities from cycle 1. Run `scripts/godot/product-cutover-check.sh --run-dir build/release-evidence/cycle-2 --previous-cycle build/release-evidence/cycle-1 --strict`, `make dev-check`, `make test-race`; record second seal digest. No default switch yet.

## Approval, switch and separate retirement

**3.1 Approved default switch — controller after sealed 2.3c/2.4c and explicit cutover approval bound to both cycle digests in ledger.** Exclusive `Makefile`, `.github/workflows/godot.yml`, `apps/mornlea-godot/project.godot`, `apps/mornlea-godot/app/host/app_root.tscn`, `packages/engine/crates/mornlea_client_core/src/bin/mornlea-desktop-launcher.rs`, `scripts/godot/desktop-release-check.sh`, audit replacement wiring and relevant guides. Make the qualified Rust server + Rust client core + G1 + embedded Python path the ordinary entry; retain an explicit previous-release rollback launcher and the exact backup identity. Test default open, remote/local, missing runtime diagnostics, mixed-runtime refusal, rollback, six-module audit and all release cases. Run cutover strict checker, `go test ./packages/audit -count=1`, `make dev-check`, `make test-race`. This is an externally consequential later action; a plan checkbox does not authorize it by itself.

**3.2 Bootstrap/pilot product-closure retirement — controller after 3.1; exclusive `apps/mornlea-godot/app/bootstrap/`, pilot shared-library selection in `packages/engine/crates/mornlea_godot/src/client_core.rs`, export manifest and corresponding tests.** Remove migration Bootstrap only after 2.1 diagnostics cover prepared/unprepared/exported states. Remove pilot Go core from selected product package/link path, keeping previous release intact. Test no Go core load, no feature GDScript, Python isolation, missing native diagnostics, 100-cycle teardown and previous release restore. Run `make godot-project-check`, `make godot-python-check`, Rust `product_cutover`, strict checker. Source deletion is not implied.

**3.3 Old renderer ABI v19 consumer retirement — controller, separate node after 3.2.** Inventory all `packages/engine/crates/mornlea_client` FFI consumers and source/export references; edit only the verified consumer list and workspace/build registration required to remove the selected product dependency. Do not mass-delete renderer files while offline tools or rollback artifacts still consume them. Test a previously live consumer absence, product closure graph, `rustup run 1.97.1 cargo metadata --manifest-path packages/engine/Cargo.toml --no-deps --format-version 1`, `go test ./packages/audit -count=1` and strict checker. Record removed versus retained paths and complete prior-release rollback.

**3.4 Go real-time source consumer retirement — controller, separate node after 3.2/3.3.** Inventory `packages/client/cmd/mornlea-godot-core`, Go server/client commands and scripts; remove only verified unused product launch/build edges, keep approved offline tools and prior release. Test direct/transitive Go process/library absence in product, no accidental removal of tool/test users, six-module Go checks and strict checker. No blanket directory delete. Record consumer graph, scoped commit and rollback.

**4.1 Final ledger and architecture reconciliation — controller.** Re-enumerate D0–T1 and supported feature/platform/visual cases, bind both release cycles and per-node retirement evidence, update guides and skill only for verified cross-task rules; missing evidence blocks closure.

**4.2 Final gate — controller:** `rustup run 1.97.1 cargo fmt --manifest-path packages/engine/Cargo.toml --all --check`, `make godot-python-check`, `make rust-check`, `make dev-check`, `make test-race`, `go test ./packages/audit -count=1`, `openspec validate --all --strict --no-interactive` on final SHA, then verify complete previous-release restore. All 2.3a onward nodes are serial; 2.1/2.2 may overlap after the test seam because their files are disjoint.
