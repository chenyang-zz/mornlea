## Why

The approved Rust-core/Godot-Python target names owners but does not provide one project-wide interface map that future independently developed tasks can cite. F2, F3 and P8–P13 each describe a slice; without a reconciled register, common identities, lifecycle and family negotiation can drift between them. The current Godot host also has symbolic audio/lifecycle requirements against a numeric-only pilot family table.

## What Changes

- Publish a bilingual target interface architecture with an ownership/dependency register, interface shapes, common identity and error rules, semantic family catalog, feature activation rules, and staged contract landings.
- Bind future target-oriented plans to that map through root guidance and documentation navigation.
- Preserve the distinction between existing F1 Rust types, pilot Go/Godot interfaces, and unimplemented F2/F3/feature contracts.

## Capabilities

### New Capabilities

- `target-runtime-interface-architecture`: a reviewable, version-aware architecture baseline for future shared-boundary plans.

### Modified Capabilities

None. Existing runtime behavior and interface-first development governance remain unchanged.

## Impact

- Affected files: `docs/runtime-interface-architecture.md` and `.zh.md`, documentation manifest/navigation, root `AGENTS.md`, cross-links in active F2/F3/P8–P14 designs, and this change's design/spec/tasks/ledger.
- Compatibility: no wire, save, ABI or schema version changes; the current v45 and versioned save/codecs remain authoritative. New family names and Rust facades are target definitions, not exported implementations.
- Concurrency/performance: no runtime effect. The map specifies boundedness and single-authority ownership; new numeric budgets require evidence at each compile-ready landing.
- User outcome: later tasks can cite one global map and know which declarations exist, which must land first, and which actor owns integration.
- Non-goals: implementing F1 closure, F2/F3 crates, a new ABI registry, complete family field schemas or product cutover in this documentation unit. Those remain independently gated OpenSpec changes.
- Rollback: revert the architecture guide, navigation and root reference; no runtime or save migration is involved.
