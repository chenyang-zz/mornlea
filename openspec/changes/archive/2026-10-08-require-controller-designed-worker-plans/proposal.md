## Why

Workers cannot reliably implement an architectural migration from broad directions alone. The controller must settle functional behavior, ownership, APIs and acceptance before decomposition, using Superpowers to produce executable task briefs instead of transferring design decisions to implementers.

## What Changes

- Require Superpowers `brainstorming` and `writing-plans` when creating or materially revising multi-step implementation plans.
- Keep architecture, functional design, edge cases, performance bounds and decomposition with the main Agent; workers implement frozen contracts and escalate discrepancies.
- Require concrete task briefs, explicit dependencies and a controller readiness check before dispatch.
- Synchronize root guidance, OpenSpec artifact rules, project orchestration skills and bilingual workflow documentation.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `development-governance`: Add controller-owned design and Superpowers task-planning requirements.

## Impact

Affected files: `AGENTS.md`, `openspec/config.yaml`, both project `mornlea-implementation-orchestration` skills and their planning reference, and `docs/development-process*` / `docs/openspec*` and their documentation-manifest revisions. The first application is the existing `rust-runtime-foundation` change. No runtime, protocol, save, ABI, dependency or thread-concurrency change. No external communication, new model configuration or plugin installation is required. Rollback is a focused reversal of this rule and its mirrors, preserving existing plans and user changes.
