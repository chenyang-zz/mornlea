## Exact values and port

Public const MAX_CHUNK_RETIREMENTS:usize=8. RetiredChunkId is a public Copy,Clone,Debug,Eq,PartialEq,Ord,PartialOrd value with PRIVATE key:ChunkKey,generation:u64. Only pub fn key(self)->ChunkKey and generation(self)->u64 are exposed; no public constructor/raw identity injection. The crate-private owner constructor derives this identity from an already-checked ReadyChunk. Managed acquisition generations are nonzero; use debug_assert on this trusted fact, not a new wire refusal. No revision is used as physical body identity.

RetiredChunk is public, deliberately NOT Clone, with private id:RetiredChunkId and body:Box<RetiredChunkBody>. Private body fields ready:ReadyChunk,drops:DropState,containers:ContainerState,observations:Option<BTreeMap<(ChunkKey,BlockPos),BlockObservation>>. All fields are existing whole owners. pub fn id(&self)->RetiredChunkId. Custom Debug prints only identity, never chunk data. pub(crate) fn new(ready:ReadyChunk,drops:DropState,containers:ContainerState,observations:Option<BTreeMap<(ChunkKey,BlockPos),BlockObservation>>)->Self derives identity and moves fields into one Box, with no per-cell operation. pub(crate) fn into_parts(self)->(ReadyChunk,DropState,ContainerState,Option<BTreeMap<(ChunkKey,BlockPos),BlockObservation>>) moves all owners out for exact restoration on refusal; the fixed Box allocation alone may deallocate on caller. No public body/read/capture mutation interface or custom production Drop. Until the later consumer supplies production calls, narrowly scoped #[allow(dead_code)] is permitted only on new/into_parts, the private body field and private RetiredChunkBody structure; unit-only use otherwise fails all-target -Dwarnings. The actual consumer removes these temporary allowances once its production calls qualify usage, without widening visibility.

RejectedRetiredChunk is public with pub error:ServerError and pub owner:RetiredChunk; metadata-only Debug. Refusal preserves the exact incoming owner, not an identity-only substitute.

ChunkRetirementPort is public:

```rust
fn submit(&mut self, owner: RetiredChunk) -> Result<(), RejectedRetiredChunk>;
fn collect(&mut self, max_reports: usize) -> Result<Vec<RetiredChunkId>, ServerError>;
fn occupied(&self) -> usize;
fn close(&mut self, deadline: Deadline) -> Result<(), ServerError>;
```

submit success transfers the whole owner for irreversible disposal, not immediate destruction acknowledgment. The provider retains one charge until actual destruction completes AND its scalar report is collected; queued+started+held<=8. Saturation returns Capacity{resource:ChunkRetirements,limit:8,observed:9} with the owner. Closed/closing submission returns InvalidState{phase:Closing} and owner; no silent discard. A duplicate retained id refuses InvalidInput{field:"chunk_retirement_identity"} with incoming owner and no charge change. Scalar identity does not retain body/capture. collect transfers at most min(max_reports,8) scalar reports in successful submission order and releases exactly those charges; max_reports0 transfers none, repeated collection is empty. No unbounded scan/history. close stops new work, finishes disposal of every accepted owner, collects completion charges, disconnects and explicitly joins the CPU owner. Timeout{operation:Retire} retains outstanding charge/handles for same-owner retry; disposal is not cancelled or replayed. Owner teardown panic is sticky Internal{invariant:"chunk retirement worker"}, cannot become joined success. Drop disconnects without claiming explicit quiescence; real provider must keep accepted owners on its worker-side channel so Drop cannot destruct queued bodies on caller. These are port obligations, not a worker implementation in this contract node.
