## Boundary and design

This is an architectural prerequisite within the approved F2 persistence scope, using existing S0 save values and S3 SaveAuthority/OwnedSnapshot contracts. The public additive `core::actor_save::ActorSaveLedger` is the only new shared surface. Its accepted SHA must precede independently reviewed state/player-cache/bootstrap consumers. No trait or synthetic implementation is added: this node implements the actual in-memory owner and exercises public consumer recipes. This is ledger/contract acceptance, not actual disk or producer integration.

Existing Go players.go, players_snapshot.go, players_completion.go, players_dispatch.go, hostiles.go and passives.go define latest-current comparison, capacity16 player entries, persisted+1 capture, immutable retries, exact-key/revision ACK, late changes and clean inactive eviction. The scheduler retains retry timing and work handoff; the ledger owns neither I/O, worker threads, cancellation, cadence nor tickets. Player prepare/name/load coalescing, missing confirmation and Active-or-ever-spawned decisions remain separate caller responsibilities. Companion bootstrap overlay/namespace/lifecycle/task normalization is a producer responsibility; this ledger never synthesizes an aggregate or erases omitted dormant records.

Chosen owner: an ordered BTreeMap with a private actor-family key derived from valid SaveValue, containing current normalized value, exact estimated length, persisted revision, sticky dirty flag, eligible flag, caller pin, force flag and at most one immutable OwnedSnapshot flight. Ordering is player UUID bytes, Companions, Hostiles, Passives. Normalize only save-envelope revision to1 and sort aggregate records/lifecycle/queues by IDs; preserve all fields and ordered task/plan contents. Revisions belong to durable targets, not semantic current comparison. Current/pending values never masquerade as disk acknowledgment. Borrowed current returns its separate persisted revision.

At most16 player keys and three singleton aggregate keys, with at most19 current values and19 selected immutable targets. Codec bounds validate every value (player payload1MiB, companion file393904bytes/64records, hostile64 and passive32 records); there are no encoded byte buffers. Target capture and ACK use at most one additional bounded value clone per key; caller/mailbox copies retain their separately accepted lane bounds (16player,3eachaggregate,4MiB encoded reservation). No global allocation or whole-runtime acceptance is inferred from these local bounds. Selection is bounded by19 entries, stages its complete chosen prefix before changing any flights, permits the first whole record to exceed count/byte budgets consistently with existing SaveAuthority selection, and takes no already selected key. Subsequent records require positive remaining count/byte capacity. Revision overflow is typed and leaves selection ownership unchanged.

New signatures (existing types unless named here):

- `ActorSaveLedger::default() -> Self`.
- `retain(&mut self, value: SaveValue, persisted_revision: u64, needs_rewrite: bool, eligible: bool, pinned: bool) -> Result<(), ServerError>`: codec checks and duplicate check precede mutation/eviction; positive persisted revision must equal input envelope revision, or persisted0 requires envelope1 as an unsaved initial value. On full player admission, evict only clean/unselected/unpinned player entries; otherwise Capacity(Players,16,17), without changing entries. Singleton duplicates refuse. Persisted0 plus eligibletrue requires needs_rewritetrue as an explicit initial save obligation; otherwise refuse without admission. A quiet absent/empty baseline uses eligiblefalse until a real change or confirmation promotes it. Eligibility is explicitly supplied, never guessed from missing or actor body.
- `observe(&mut self, value: SaveValue, persistable: bool, force: bool) -> Result<bool, ServerError>`: refuses unknown keys; normalize/validate before changes. Replace latest current on semantic change. Eligibility only promotes, and dirty becomes sticky for an eligible semantic change or promotion. Force is retained only for eligible entries. Return whether current changed, independent of the dirty transition. No capture occurs.
- `set_pinned(&mut self, key: &SaveKey, pinned: bool) -> Result<(), ServerError>`; the caller pins prepared, active or otherwise non-evictable players. Unpin does not discard dirty/flight ownership.
- `current(&self, key: &SaveKey) -> Option<(u64, &SaveValue)>`: persisted revision and normalized current, borrowed without copying.
- `select(&mut self, mode: SaveMode, budget: SaveBudget) -> Result<Vec<OwnedSnapshot>, ServerError>`: eligible dirty unselected entries; Urgent requires force. Stamp checked persisted+1; target urgency Unload for force, Autosave otherwise. Keep full exact flight identity before returning owners. Selection clears consumed force; a later force belongs to the next target.
- `has_target(&self, key: &SaveKey, revision: u64) -> bool`; `matches(&self, snapshot: &OwnedSnapshot) -> bool` compare exact selected owners with bitwise float identity, independently of source IEEE semantic current equality.
- `validate_saved(&self, snapshot: &OwnedSnapshot) -> Result<(), ServerError>`: same-key/revision altered value/estimate/urgency is a hard identity error; stale/unselected revision is ignored. This is the preflight for a future whole mixed-cohort authority validation.
- `saved(&mut self, snapshot: &OwnedSnapshot) -> Result<bool, ServerError>`: exact owner ACK advances persisted revision, clears its flight, recomputes dirty by latest semantic equality; preserves late force only when still dirty. Stale ACK returns false. Failure/retry holds the original flight until exact success or refusal return.
- `return_dirty(&mut self, snapshot: &OwnedSnapshot) -> bool`: exact refused owner returns to selectable current and restores force when the target was urgent; forged/stale owners do nothing. Actual failed admitted writes keep their flight charged for scheduler retry and never call this refusal operation.
- `stats(&self) -> SaveStats`; `save_keys(&self) -> Vec<SaveKey>` count eligible unsaved latest and flights without duplicating identical content; bytes include a distinct newer dirty current beside its immutable flight. Keys are ordered unique outstanding identities.
- `freeze(&mut self)`: fences retain/observe/pin/select with InvalidState(Closing); ACK/refusal return and pure observations remain possible, retaining all old ownership. The runtime chooses the freeze point after final accepted capture.

## Independent-review corrections before acceptance

Two Important findings change this not-yet-landed contract: valid absent-respawn NaN cannot use derived float equality for immutable identity, and eligible initial revision-zero admission must explicitly own a save obligation. Main first adds six actual regression REDs: one legal NaN payload, signed-zero forgery in each of four families, and clean eligible initial admission. Exact snapshot comparison uses scalar/key/revision/estimate/urgency equality plus bitwise floats. Player comparison excludes respawn_position from ordinary PartialEq and compares those bits directly, preserving legal absent NaN; all other player/aggregate float lanes also compare bits. Semantic current equality remains Go IEEE: signed zero is equal, NaN is unequal. ACK normalizes one bounded target clone and recomputes semantic dirty, so a legal NaN target can advance its durable revision while remaining source-semantically dirty. New initial-eligibility guard rejects persisted0/eligibletrue/needs_rewritefalse; callers represent a quiet absent aggregate as ineligible until a source change, and actual missing confirmation promotes eligibility. This rule does not infer aggregate startup/bootstrap acceptance. No source payload is discarded or forcibly normalized beyond envelope/order. Run six corrections before product edit, then all20public ledger tests and complete commit gates on corrected source.
