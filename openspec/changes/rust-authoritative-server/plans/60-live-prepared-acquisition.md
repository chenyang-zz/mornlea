# Prepared chunk installation at the actual acquisition phase

**Goal:** Transfer actual background load/generation records into live authoritative Ready state at the existing Acquire row, with bounded identities and availability.

**Architecture:** One serial actual consumer of accepted prepared/load contracts and providers, generation owner, resident ownership and immutable chunk views. The authority owns one private lifecycle book and at most16 staged owned results; preparation stays off tick. Later runtime request driving, source subscription/safe placement, durable selection and unload/reclamation consume this accepted implementation serially. They are excluded here, so this packet does not claim full chunk lifecycle or gameplay completion.

## Enable, requests and phase transitions

enable_live_chunks is idempotent once enabled. Initial enable requires Running and empty resident blocks/Ready/drops/sparse containers/container chunks/dirty chunk set and empty legacy chunk-result queue; actors/inventories/logins may exist. It prevents mixing sparse fixture world data into a live managed world. Existing replay/harness mode remains unchanged. Raw legacy admit_chunk rejects original owned input in live mode; legacy cancel_chunk becomes no-op in live mode and cannot append tombstones. Actual prepared lane is the only live chunk admission path.

replace_chunk_wants validates count before consuming/replacing the set. Loop only existing capped book: update wanted; Ready forgotten ->Unloading; Unloading wanted again ->Ready retaining generation/body/facts; Failed or NeedsGeneration forgotten -> remove no-payload record. Loading/Generating retain even forgotten/unbound, because an external provider may already have started before bind. No cancellation of a started forgotten attempt. Keep Unloading bodies for subsequent durable/reclamation consumer, unavailable to gameplay. New desired keys do not allocate records until a reservation succeeds; therefore moving a full view cannot double the managed population.

reserve load requires wanted and absent/Failed record, free load lane and managed population capacity; increment checked global generation and replace/create Loading with requestNone, no body. bind requires matching unbound reservation and unique alias in load lane; record requestSome; duplicate alias is InvalidInput("chunk_request_identity"), existing owner unchanged. abort requires matching unbound reservation, retires lane, becomes Failed with original error if wanted or removes if forgotten. It cannot abort a bound attempt. reserve generation requires wanted NeedsGeneration, free generation lane; transition Generating requestNone, same generation; bind/abort follow the same source-specific rules. Wrong/stale reservation is InvalidInput("chunk_reservation"). No method fabricates successful provider cancellation or retirement.

offer validates mode/phase, staged capacity16, current bound source/request/key/generation, no duplicate staged alias, and successful PreparedChunk key/generation matches outer fields; refuse owned event unchanged with InvalidInput("chunk_completion_identity") for mismatch/duplicate. Original expected alias remains until Acquire consumes its staged event. Do not require wanted at admission: a forgotten started completion still matters. Accepted typed Failed event carries its error without mapping corruption/future to absence.

Existing world_acquisition::run validates its RuleCall shape then calls new TickContext::apply_live_acquisition() for enabled mode; disabled/no queued batch returns historical zero. At most16 queued events sort by source Load before Generated, then ChunkKey, matching separate source load/generated application order. At this existing row after CompanionIntent and before player physics, revalidate expected current alias, settle its lane/alias, and apply:

- Load None +wanted ->NeedsGeneration; forgotten -> remove; no native generation on tick.
- Load Some or Generated Ok ->move prepared Ready/drop/container values into the current context maps, preserve generation/revision/persisted/rewrite/recovered facts; wanted ->Ready, forgotten ->Unloading. Never publish Ready for forgotten data.
- Error ->Failed with original error while wanted, otherwise remove record; no generation for corrupt/future/I/O failure.
- Stale internal alias ->count rejected, drop only this owned event, preserve current record. This arm is defensive; public offer already rejects stale events.

PhaseReport examined is drained count, applied counts successful state transitions including missing, rejected counts failures/stale, carried0. Commit already advances Ready revision once via changed-key finalization; reflect latest generation/revision into corresponding live facts there. Do not treat persisted revision/rewrite as saved, or clear them here. No writes to store/retry scheduler or autonomous durability claim.

PreparedChunk::try_new prepares DropState and ContainerState off tick from validated fixed physical slots; add private into_live_parts moving Ready+DropState+ContainerState+durability facts. Preserve existing public into_parts signature and codec/raw behavior. No Ready snapshot/materialize during installation, no physical slot Vec rebuilding on tick. Existing chunk data base and page ownership stay immutable/shared.
