## Actual provider exact API and ownership

Create transport/live.rs with public `LoginDriver::new()->Self`, Default, `pending()->usize`, `stop_new(&mut self)` and `bind<'a>(&'a mut self,authority:&'a mut AuthorityState,loads:&'a mut dyn PlayerLoadPort)->LiveEndpoint<'a>`. LiveEndpoint borrows those three owners only and implements TransportSessionPort, PublicationPort and unchanged TransportAuthority. It never implements full ServerEndpoint. Authority remains root/runtime-owned; all IO stays in existing load port. No hidden Arc/Mutex/state clone, OS worker or storage handle duplication.

Driver retains at most16 BTreeMap<LoginTicket,Record> entries, charged queued/loading/Ready until commit/cancel; Record contains session,player and Loading/Ready/Cancelled state only, no stored body or request history. Last cancellation error Option<ServerError> is one bounded diagnostic. No committed-ticket tombstones. `begin_login`: reject stopped with InvalidState(Closing), driver16th/17th cap PendingLogins16/17; get player then authority.prepare(login,kind), call loads.start(player,deadline), and insert returned ticket. Start failure retires only newly Prepared session with PeerGone and returns original error; no occupied-slot leak. Duplicate load ticket is Internal(login load ticket identity), retires new reservation and never overwrites/cancels older ticket (actual accepted load provider never repeats). Preparation retains existing phase/player capacity/duplicate identity precedence. Deadline passes unchanged; common connection core owns observed clock/deadline cancellation, so provider does not invent an Instant::now check over virtual Clock inputs.

`poll_login`: unknown/consumed Pending. Ready returns newly owned small LoginSuccess(player,world_seed as u64), same session, without re-poll/reinstall. Loading polls once; Pending unchanged; Loaded(stored) moves directly into authority.install and marks Ready only after success. Failed load/install removes ledger and retires Prepared session, returning LoginPoll::Failed with original error and exact existing codes: Io Load InvalidData or InvalidInput from decoded/player install ->LOGIN_PLAYER_DATA_CORRUPT; Timeout Load or other Io ->LOGIN_STORE_UNAVAILABLE; Internal/InvalidState/StaleSession/other capacity ->LOGIN_INTERNAL_ERROR. No custom wire reasons. A failed/cancelled load never installs canonical new player; only Loaded(None) does.

`commit_login`: only owned Ready; authority.activate then remove ledger and return session. Unknown/Loading/Cancelled rejects InvalidInput(login_ticket); failed activation keeps record for cancellation. Second commit cannot reactivate. Session/actor safe placement remains later node, not implied by transport Active. `cancel_login`: unknown no-op; retire session only if still Prepared, mark Cancelled, attempt loads.cancel. Success removes ledger; failure retains Cancelled alias+bounded last error for retry and suppresses all late Ready outcomes. Cancelled poll retries cancel and returns Pending, never publishes. Add `pub fn cancel_pending(&mut self,authority:&mut AuthorityState,loads:&mut dyn PlayerLoadPort)->Result<usize,ServerError>` stops new admission, visits original at-most16 tickets once in order, uses same cancellation, returns number removed or first exact retained cancellation error while already removed records remain removed. Subsequent same-owner retry drains remaining; no dropped ownership or stranded Prepared capacity.
