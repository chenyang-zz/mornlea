## Ordered transitions and failure policy

advance on completed refuses InvalidInput{field:"restore_complete"} before reads/mutation, preventing duplicate activation. Otherwise:

1. For each unassessed restore candidate, invoke candidate_chunks BEFORE full validate_restore and add its keys. Only InvalidInput actor_geometry from horizontal enumeration is an ordinary unrepresentable candidate: retain no keys for it and still use validate_restore, which returns assessed invalid. Other errors propagate unchanged. Invalid Y still retains valid X/Z keys. If !ready return Waiting at the SAME next_restore without considering Safe or spawn. If valid, return activation at its exact candidate dimension/position and check.on_ground, mark completed, set current spawn_dimension to chosen dimension, clear restore candidates/index/wanted and best/exhaustion; retain ordered columns/spawn_wanted privately. If assessed invalid increment next_restore and continue in THIS call. No water tier applies to restore.
2. Once restore candidates are exhausted, Companion clears restore_wanted before any spawn work; Player retains all rejected keys until activation. If exhausted_revisions exists, compare sorted column positions in current dimension using ready_revision. All identical Ready observations return Exhausted with no column/block/height reads. Any missing/non-Ready/different revision resets next_column0, bestNone and exhausted_revisionsNone; do not retry previously assessed restore candidates.
3. For each remaining ordered column, retain its ChunkPos in spawn_wanted BEFORE calling accepted scan_spawn_column with current spawn_dimension/eye_height. !ready returns Waiting at the same index and preserves the GLOBAL best from earlier columns; the column utility's own abandoned local fallback stays discarded. A Dry site activates immediately grounded=true. Other present sites replace global best ONLY if strictly better: EyeDry outranks Submerged, equal keeps first nearest/X/Z. Increment index after a ready assessed column. Source scans all remaining ready columns within the same advance call; no newly invented column quota, alternate clock or partial publication is introduced.
4. At end, activate best if present with grounded=true WITHOUT current revalidation. Source deliberately preserves the previous chosen site across a readiness gap; later PLAYER unstick/reset is a separate consumer, while source companions have no such recovery. No best means capture all current Ready revisions in sorted column-position order and return Exhausted. Any missing/non-Ready during this final capture returns Internal{invariant:"restore exhausted chunk"}, source's impossible exhausted-chunk panic as typed trusted failure. Never fabricate an exhausted revision. A real consistent PlacementWorld makes this unreachable; a private inconsistent-reader injection exercises it.

advance forwards geometry/collision/eye/certificate errors at the exact invoked helper stage. It does not promise rollback of already retained wanted/scanned progress on a trusted error; the later authoritative failure fence stops such state. Eye height is validated by scan_spawn_column only if spawn is actually attempted, so a valid restore may activate before reading an irrelevant eye value. No extra prevalidation changes source fallback order.

restart_player requires kindPlayer AND completed=true FIRST, else InvalidInput{field:"restore_restart"}. Its candidate count is<=1 (the later death owner's optional bed Current; mere geometry recovery supplies empty), else restore_candidates; all refusal checks precede self mutation. On success preserve kind/anchor/radius/ordered columns/unique positions/existing spawn_wanted, install supplied current dimension and move admitted candidates into a fresh Vec requesting capacity1 (discard arbitrary caller spare allocation), reset restore index/wanted, next_column0/best/exhaustion/completedfalse, insert anchor into spawn_wanted. This models the scan component of source active beginReset; actor motion321/oxygen/control/mining/health/hunger/death/safe/bed handling is NOT performed here. It is illegal to restart a still-pending owner or a companion through this player-only API. Removing a disconnected actor later drops its small owner; no background obligation exists.
