# Preserve the world lease throughout backup restoration

**Goal:** Refuse restoration while any managed world writer holds its native lock, and retain one lock inode and exclusive descriptor throughout actual backup copying, installation, verification and manifest publication.

**Architecture:** The opt-in shell remains the CLI/process owner. One private Python helper owns the offline restore attempt, its native flock, bounded-memory filesystem work and checkpoints. A staged backup shares the original lock inode; atomic directory exchange keeps the canonical world present throughout new installations. The original world then retires beside it under the same lock. The actual sealed Go verifier and subsequent Go startup remain separate existing consumers. No shared Rust contract or parallel prospective consumer is introduced.

## Native ownership and filesystem algorithm

1. Read the manifest at most1MiB, reject duplicate JSON fields, require exact supplied world/backup/nonce bindings and a recognized restore_stage. Validate canonical confined paths and regular non-symlink roots/manifest/backup identity. Identity at most4096 bytes, nonempty source and migration_version1; preserve existing source/seed acceptance rather than inventing a new backup identity. Stream backup hashes using1MiB chunks and exact existing path/zero/u64-length/content ordering, excluding the existing lock/backup identity basenames. Reject symlink/special tree entries. Compare the recorded backup_tree_sha256 before mutable restore work. Memory is one chunk plus bounded manifest/identity and sorted path metadata; copying is explicitly offline, never an authority hot path.
2. For ordinary/staged/backup_installed current layouts, use world/world.lock; for a recognized legacy missing-current old_retired/staged crash layout, use retired/world.lock. Open O_RDWR|O_NOFOLLOW|O_CLOEXEC without creation. Require a regular descriptor with positive link count, native device/inode matching manifest lease_identity. Take LOCK_EX|LOCK_NB; a held lock is writer_live. Revalidate the same path/device/inode after locking. Retain this unique descriptor through every subsequent step and error; finally close once. No FREE probe substitutes for it. Callback `locked` occurs after successful correlation before mutation.
3. Require the native operation before creating/changing a staged world: Linux libc renameat2(AT_FDCWD=-100, old, AT_FDCWD, new, RENAME_EXCHANGE=2); Darwin libc renamex_np(old,new,RENAME_SWAP=2). Set exact ctypes arg/restypes and errno handling. Native errors are restore_failed with retained artifacts. No unsafe Rust, syscall-number guessing or fallback. A separate no-replace operation is allowed only for retiring a private sibling or returning an existing legacy retired world: Linux RENAME_NOREPLACE=1, Darwin RENAME_EXCL=4. Foreign destination collision refuses without overwriting it.
4. Fresh attempt requires current world and no retired directory. A stale private staged directory may be removed only for this manifest nonce after validating its regular confined tree; never remove a retired world for a fresh attempt. Copy the verified backup into the staged sibling, preserving regular file/directory metadata and syncing each file, children then staged root. Do not copy the root backup identity or root world.lock. Create staged/world.lock as a hardlink to the held original inode and sync the staged root/parent. Existing copied-lock staged fixtures may replace that regular copied lock only while an additional nonblocking exclusive descriptor for it is retained; an active foreign stage writer refuses before unlink. Retain that descriptor until the attempt ends. Check the staged content hash equals backup_tree_sha256.
5. At staging, record restore_stage=staged plus restore_original_tree_sha256 and restore_directory_identity=`<dev>:<ino>` for the original world directory. These additive schema1 checkpoint fields describe restore ownership only. Atomically publish manifest JSON via unique sibling, file fsync, replace, parent fsync. Callback `staged` follows the durable checkpoint. A preexisting legacy staged checkpoint without these fields acquires them under the held original lock before changing directories.
6. Before exchange, current directory must match recorded original directory identity, staged must be the verified backup, and both root lock paths must resolve to the held inode. Atomically exchange world/staged, then sync the parent. Canonical world never disappears; its lock inode remains identical. Callback `swapped` occurs now, before publishing restore_stage=swapped. Staged now contains the original world. Revalidate directory identities and both hashes to qualify the transition; arbitrary collisions/foreign roots refuse.
7. Move the original world from staged to the previously absent retired sibling with native no-replace rename and parent fsync. Callback `retired` follows this durability boundary before publishing backup_installed. Verify canonical installed world hash equals backup, its lock matches the retained inode, and retained original directory identity is at retired. Atomically publish restore_stage=backup_installed, unchanged original lease_identity and world_tree_sha256=backup_tree. Callback `installed` runs before releasing the lock. Return the retired path; existing shell verifier/startup/retired cleanup runs afterward. The backup tree and identity never change.

## Crash and refusal rules

- Missing/unrecognized stage, unsafe paths, absent lock or recorded identity mismatch -> invalid_manifest/identity_mismatch; lock contention -> writer_live; invalid backup/hash -> backup_mismatch; filesystem/native/copy/barrier/transition failures -> restore_failed. Preserve causes and artifacts; never report successful restoration after an uncertain barrier.
- stage=staged with original directory at world means exchange is pending; with original directory at staged and exact backup at world means exchange already happened before the checkpoint, so continue without swapping back. Compare directory identity, never choose roles from equal hashes alone. Both trees must match their recorded role hashes.
- stage=swapped with original directory at staged means retirement pending; original at retired and exact backup at world means rename already happened before the checkpoint. Resume qualification and publish backup_installed. No nesting/overwrite of an existing retired directory.
- stage=backup_installed verifies installed backup/held inode and retained original directory when present, then returns idempotently. If the previous writer is live, even this direct helper refuses. Normal top-level PreviousRunning idempotence remains the existing login/lock consumer and does not invoke restore.
- Legacy backup_installed with absent original role fields may qualify those fields only after installed backup hash/current held identity, regular distinct retired directory and its same held lock inode all validate; retain retired directory identity and its actual streamed hash under that guard, then publish atomically. If retired is absent, verify current backup/held identity and return idempotently without fabricating original role fields. Differing current/retired lock inodes refuse identity_mismatch before any mutation. Callback/crash proofs distinguish this defensive legacy qualification from ordinary fresh installation.
- Legacy old_retired or staged-after-retire with current absent and original retired present: acquire/correlate that original lock and durably publish its directory/hash roles as old_retired BEFORE native no-replace retired->world. A qualified current-present/retired-absent retry must match that exact directory, hash and held inode and repeat the parent barrier. Normalize and revalidate the staged backup under the held owner regardless of whether role fields already exist; recopy a missing stage, bind the same lock inode, remove only backup identity, sync and publish staged before ordinary exchange. Foreign/unqualified current or a still-present retired collision refuses. A historical backup_installed layout with differing current/retired lock inodes refuses identity_mismatch; no automatic rebinding of potentially separate writer lineages.
- If an exception/crash follows actual exchange/retire but precedes manifest publication, retained directory identity/hash/inode proofs select the continuation above. Kill releases only this process's flock; restart must reacquire before mutation. Successful guard release precedes the actual Go verifier, which takes its own existing native lock; a racing writer makes that verifier/startup refuse. Do not claim atomic transfer of a descriptor to the sealed Go runtime.
