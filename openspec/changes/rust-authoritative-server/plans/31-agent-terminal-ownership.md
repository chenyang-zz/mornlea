## Frozen behavior and private ownership

1. Poll is a peek. Each plan/dialogue slot records private terminal_transferred=false on admission. When a matching terminal response is successfully enqueued, set that flag together with queue ownership; complete its snapshot only once. A full queue retains the untransferred terminal response for next drain. Do not poll a transferred slot. Keep frozen identity/semantic install slot until installation, independently of HTTP retirement.
2. Capture every terminal request ID before semantic settlement and invoke AgentHandle::cancel(id,Deadline::at(clock.monotonic())) to retire the already-finished owned worker. Successful retirement removes its ownership exactly once. Failed retirement enters an owner-private BTreeSet of IDs, cap64. Reap that ledger with the same zero-wait deadline at the start of subsequent drain/poll/admission calls; never re-emit its semantic result. Do not treat an unsuccessful retirement as success or replace it with detached ownership.
3. Before each new owned business submit (including CancelRun), reserve total active untransferred HTTP requests plus pending retirements below64. Transferred already-retired semantic slots do not count as HTTP ownership. Refuse existing Resource::AgentRuns Capacity{limit:64,observed:65} before wire/thread work if no room. The terminal transfer conserves a reserved ownership slot, so adding its ID cannot exceed the bound. Keep host's existing stricter combined worker/task/outcome caps.
4. Every host success/failure terminal branch retires the original request. Independent CancelRun uses the existing100ms off-tick failure budget. Return its admitted ID when it remains pending or retirement fails, so the host retains and retries it rather than leaking. On terminal CancelRun outcome retire immediately. No new cleanup submit occurs without capacity; best-effort cleanup may refuse before work. The independent cancel record is fenced by its original lease/run identity as before.
5. A response polled for a request is that owned worker's immutable terminal result. Invalid echoes can never produce a later corrected result for the same request. They fail/reclaim only that current request's gate and snapshot, and never alter another request or newer attempt. Reconcile the FIFO ScriptAgent fixture which currently returns multiple contradictory terminal responses for one ID. At tick install, a queued stale outcome with attempt/request different from a newer slot leaves that newer slot untouched; a matching current request with permanently invalid response identities releases its own semantic slot after the existing StaleIdentities rejection. Update private source docs accordingly, without inventing a wire outcome.
6. Memory commit/reconcile/delete polls capture a terminal inflight record once, apply existing settlement once, remove that HTTP inflight record on all terminal branches, and retire its provider request. Malformed delete emits Fenced once, retaining mirror/epoch/reservations. Keep its delete intent (new epoch/tombstone) separately from request ownership in a bounded private map for later explicit retry/finalizer; it must not keep polling the dead request. Commit reservations likewise survive refusal/failure per existing policy. Successful delete clears the corresponding semantic intent. Public ordinary memory methods remain callable as before.
7. Preserve all unrelated retry/epoch/identity/backoff decisions. Finalizer begin/drain and shared shutdown Agent ownership remain separately pending3.9d6; do not claim or implement them here.

## Test-first acceptance
