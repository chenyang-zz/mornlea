## Exact contract and algorithm

Add private snapshot: mornlea_domain::ChunkSnapshot to EncodedChunkSnapshot. Add snapshot(&self) -> &mornlea_domain::ChunkSnapshot and into_source_parts(self) -> (ChunkSaveView, mornlea_domain::ChunkSnapshot, usize, PreparedFrame). The tuple order is capture, snapshot, section_payload_bytes, frame. Neither method performs validation, expansion, packing, framing, allocation, cloning or I/O; all validation has already succeeded on the actual factory. The consuming method returns (self.capture, self.snapshot, self.section_payload_bytes, self.frame). It preserves exact capture Arc identity, the semantic section/palette/word allocations and original frame bytes/allocation.

EncodedChunkSnapshot::encode extracts network_snapshot once OFF TICK, converts Event::ChunkSnapshot(snapshot.clone()) into the existing ServerPacket and encodes once, then retains the original semantic snapshot. The clone and conversion remain on the CPU owner. Extraction errors retain chunk_network_snapshot, conversion/codec refusal retains packet; failure returns no successful result. Existing getters and into_frame remain compatible; into_frame drops unused semantic/capture owners. No caller can construct or replace private fields. Non-Clone result ownership and actual pool cap8/one-or-two owners, cancellation charge, timeout and joined-close remain unchanged. Each held result additionally retains one fixed24-section checked column; its palette/word bounds are the established domain bounds. Section charge remains precisely network section bytes (AIR48, loaded indexed fixture2100, edited fixture2098), excluding envelope/compression/cache memory; it is not a general memory accounting claim.

Reject reconstruction or decoding at consumption because that repeats unbounded section/codec work on tick and loses allocation ownership. Reject an Arc-wrapped semantic snapshot because existing TickPublication/Event consumes the owned value. Reject changing domain/protocol conversion here because established packet ownership needs no shared API revision. The off-tick clone is a bounded compatibility cost; later publication must avoid cloning this retained body again. Source order, current-generation/revision relevance, cancellation, asynchronous selection, whole-publication preflight and actual runtime/shutdown composition are explicit separate nodes, not accepted by this contract.
