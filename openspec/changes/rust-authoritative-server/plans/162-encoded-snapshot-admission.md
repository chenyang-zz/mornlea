## Exact method and algorithm

Add public AuthorityState::enqueue_encoded_snapshot(&mut self, session: SessionKey, expected: &ChunkSaveView, encoded: EncodedChunkSnapshot) -> Result<EnqueueOutcome, ServerError>, using existing fully qualified type paths if imports are unnecessary. In order:

1. Compare encoded.capture() == expected; mismatch returns InvalidInput{field:"chunk_encode_capture"} before session lookup, dropping only supplied result ownership. Equal key/generation/revision with a different token also refuses. No codec/section scan/materialization.
2. Look up exact session; unknown returns StaleSession{session}. Nonactive retained session or closed outbox returns Closed before source-view checks. Session Active is transport lifecycle, not observer actor Active: Pending observers remain eligible when their source view exists.
3. Require existing SessionView, existing chunks entry for expected.key(), and view.wanted containing that key; otherwise InvalidInput{field:"chunk_snapshot_publication"} without queue/history changes. Do not synthesize a view, wanted subscription or mirror entry from an encoding result.
4. Copy scalar key/revision from the matched immutable capture, move encoded.into_frame() into the existing enqueue_prepared. Its existing saturation owner retires only that recipient and retains prefix, returning Closed. No frame/byte clone or second preflight/encoding.
5. Only Queued calls accept_publication_mirror(session,ChunkSnapshot{key,revision}); Closed/error never advances sent/revision or clears resync. Return the exact existing receipt.

The caller owns source selection, request cancellation, current capture generation/revision relevance and desired snapshot order before this method. This adapter does not claim stale-worker filtering, select source candidates, compare a fresh capture token (every capture differs), wait, start workers, expand sections, encode or create a fallback. Current synchronous source projector/publisher remains unchanged and unaccepted as off-tick assembly. Existing manual source publisher's scalar snapshot revision policy remains unchanged; this method does not add an ACK or infer current generation from wire metadata. Later asynchronous producer must correlate its exact pending record and validate obsolete/cancelled results before this consumer; those decisions remain a separately designed node, not an implementer choice here.

Rejected generic PreparedFrame metadata inference because frame alone lacks generation/token and decoding on tick violates ownership. Rejected updating all generic enqueue_prepared snapshots because existing opaque owners intentionally carry no source correlation. Rejected numerical capture equality because same tuple can retain different pages/slots. Rejected accepting a new context from a result because obsolete/wrong subscriptions would manufacture history. Rejected broad async/runtime assembly inside this consumer node because candidate selection/cancellation/phase and result ownership require separate concrete acceptance; no new trait solely for isolation.
