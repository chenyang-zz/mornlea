# Passive source Snow capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. OpenSpec tasks.md is the sole status source; the steps below do not create a second checklist.

**Goal:** Retain passive-cow Snow travel/cell memory across actual ticks, capture each surviving cow's sample inside the native movement pass before quiet removal or death settlement, and settle captured original coordinates in the existing late Snow write region after source-player Snow and before legacy generic Snow, with no double collection.

**Architecture:** One module-private fixed-capacity `PassiveSnowBook` — 32 tracker slots `Option<(PassiveId, PassiveSnowTracker)>` (explicit occupancy, no sentinel id) plus a 32-cell pending batch — is a retained `AuthorityState` field (`passive_snow`, beside `source_players` at state.rs:237) loaned through the tick like the accepted source-player book (take step.rs:231, return step.rs:282-285). Capture is a per-actor `note` from `advance_movement` with the already-held pre-step/settled poses. Public `passives::run(ctx, call)` (passives.rs:198) keeps its exact signature and behavior for every existing consumer (e.g. tests/server_replay/passives.rs:718); the actual tick calls a new `pub(crate) fn run_with_snow(ctx, book, call)` over one shared private body, which at movement-loop entry after spawn registers EVERY current resident id — including fresh/graze cows, so first-tick exclusion holds even with an empty book — so `crops::collect_snow_samples` skips exactly those registered `ActorKey::Passive(id)` rows; unregistered legacy fixtures keep collecting generic Snow. Settlement reuses `crops::settle_captured_source_snow` in ≤8 slices in the existing late region. No public shape change: `ActorRuntime`/`ActorAux::Passive`, `FootprintSchedule`, `physics` and `Cargo.toml` stay byte-identical.

**Tech Stack:** Rust1.97.1, existing mornlea_server owners; no dependency, version, protocol, save, Go or native change.

**Spec:** ../design.md and ../specs/rust-authoritative-server/spec.md. This is one passive Snow integration under3.7; nonplayer speed scaling (3.7l3ns0, accepted) is untouched; all other 4.1/4.2 gaps stay open.

## Verified source and chosen owner

Rejected: growing `ActorAux::Passive` (public, widely constructed); a tick-context `BTreeMap` history (unbounded loan churn); a blanket `ActorKey::Passive(_)` skip (breaks qualified legacy fixtures); an immediate Snow write in the movement pass (moves the write region). Restart admits residents with no runtime lane and no book occupancy (`admit_residents`, passives.rs:261-285), matching Go transient discipline.

## Exact private interfaces and algorithms

`PassiveSnowTracker` (passives.rs, module-private) duplicates the accepted `SourceSnowTracker` (source_player_restore.rs:70-108): `travel: f32, cell: BlockPos, cell_valid: bool`, Copy/Clone/Debug/PartialEq, manual Default zero/ORIGIN/false; same preview — `dx = after[0]-before[0]`, `dz = after[2]-before[2]` f32, `(f64::from(dx*dx+dz*dz).sqrt()) as f32`, `travel += distance` f32; `<0.6` commits travel only; a crossing resets travel to0, runs `actor_placement::snow_cell(after)?` (checked floors, no probe), suppresses a same-cell resample, otherwise remembers the dimensionless cell (even non-Snow) and yields one candidate.

`pub(crate) struct PassiveSnowBook` in passives.rs, stored by state.rs; manual `Default`; fixed size, no heap in the new book/registration/settle path (existing `resident_keys` Vec and other provider allocations unchanged):

- `slots: [Option<(PassiveId, PassiveSnowTracker); 32]` — occupancy is the `Option`, never a sentinel id. `note` is lookup-or-insert: a matched slot keeps its tracker (a note never resets an existing id); an absent id inserts a fresh `Default` in the first free slot. Id reuse is handled by an explicit reset event, not lookup: `insert_spawn` and `admit_residents` reset the id's slot at admission, and a bounded reconcile at movement-loop entry forgets slots whose ids left the residents while queued candidates survive. A full-table insert with no free/matching slot is `Internal{invariant:"passive snow trackers"}` (passive cap 32). `PassiveId` is the existing Copy payload of `ActorKey::Passive`.
- `pending: [crops::FootprintCell; 32]`, `len: usize`; `append(dimension, pos)` preflights `len < 32` else `Internal{invariant:"passive snow capacity"}`; the append preflight and checked `snow_cell` precede the tracker commit, so any refusal leaves tracker and prefix byte-exact. No sort/dedup; collection order is ascending `PassiveId` (sorted `resident_keys` iteration).
- `fn note(&mut self, id, dimension: Dimension, before: [f32;3], after: [f32;3], on_ground: bool) -> Result<(), ServerError>`: `!on_ground` returns Ok, tracker untouched (airborne neither accumulates nor clears); otherwise preview + preflighted append. Home rollback passes before==after (`settled = pose`), travel gains exactly 0. The fresh skip (passives.rs:586-599), graze freeze and quiet removal (:708-719) return before `note` is reachable.
- `fn forget(&mut self, id: PassiveId)`: clears only that tracker slot; `pending` candidates survive removal, death and retirement. Called from the quiet-removal site and from `settle_deaths` for every staged death.
- `fn settle_snow(&mut self, context: &mut TickContext<'_>) -> Result<PhaseReport, ServerError>`: refuse `len > 32` (capacity invariant) before any read, then `crops::settle_captured_source_snow` (crops.rs:518-539) on successive in-order ≤8 slices (its `>8` guard never fires), summing examined/applied (carried/rejected 0); only a fully successful return sets `len = 0`. Reuses the accepted fresh-read transaction (`settle_snow_cell`, crops.rs:545-559); no parallel Snow transaction, no generic-schedule participation.
- cfg(test)-only `snow_test_snapshot`/`snow_test_state(id)`/`snow_test_set_state(id, ..)` mirror the accepted player helpers (source_player_restore.rs:138-163); lib unit tests only.

Entry split: `pub fn run(ctx, call)` keeps its exact signature, delegating to private `fn run_with(ctx, book: Option<&mut PassiveSnowBook>, call) -> Result<PhaseReport, ServerError>`; the `None` path registers nothing and never `note`s, so `run` stays behaviorally byte-identical for every existing consumer (tests/server_replay/passives.rs:718 and all others). `pub(crate) fn run_with_snow(ctx, book: &mut PassiveSnowBook, call)` runs the same guard/environment, then at movement-loop entry — after `advance_spawn`, before the first `advance_movement` — reconciles the book against current resident ids (admission resets, absent-id forgets, queued candidates retained) and calls `ctx.register_native_passive_snow(id)` once per resident key (fresh/graze included), so the late generic collector qualifies exactly this tick's actual-owned ids and no newly seen passive falls through to duplicate collection. Capture: `advance_movement` calls `book.note(id, record.dimension, pose.position, settled.position, settled.on_ground)` after the rollback decision and staging, surviving path only; the id comes from the matched `ActorKey::Passive(id)`. Loan/failure: the book is taken/returned around the context exactly like `source_players`; a failed tick retains candidates and trackers with no motion-rollback claim; abandoned loans never touch the book. Late settle sits after source-player `settle_snow` (players by session) and before `crops::settle_snow_footprints` — the Go players-then-passives order. Exclusion is qualified: only registered ids are skipped, so unregistered fixture passives keep the legacy path and `FootprintSchedule`'s public behavior is unchanged; any existing generic crops case affected gets its expectation update justified in the same edit and reported to ROOT. No double collection: registered passives never enter `FootprintSchedule.snow_pending`; passive candidates never enter `SourcePlayerBook.snow_pending`.
