# Passive source Snow capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. OpenSpec tasks.md is the sole status source; the steps below do not create a second checklist.

**Goal:** Retain passive-cow Snow travel/cell memory across actual ticks, capture each surviving cow's sample inside the native movement pass before quiet removal or death settlement, and settle captured original coordinates in the existing late Snow write region after source-player Snow and before legacy generic Snow, with no double collection.

**Architecture:** One module-private fixed-capacity `PassiveSnowBook` — 32 tracker slots `Option<(PassiveId, PassiveSnowTracker)>` (explicit occupancy, no sentinel id) plus a 32-cell pending batch — is a retained `AuthorityState` field (`passive_snow`, beside `source_players` at state.rs:237) loaned through the tick exactly like the accepted source-player book (take at step.rs:231, return after the context drop at step.rs:282-285). Capture is a pure per-actor `note` called from `advance_movement` with the already-held pre-step/settled poses. The public `passives::run(ctx, call)` (passives.rs:198) keeps its exact signature and observable behavior for every existing consumer (e.g. tests/server_replay/passives.rs:718); the actual tick calls a new `pub(crate) fn run_with_snow(ctx, book, call)` wrapper over one shared private body, which registers the book's owned ids on the tick context so `crops::collect_snow_samples` skips exactly those registered `ActorKey::Passive(id)` rows — legacy fixtures that stage passives without registration keep collecting generic Snow. Settlement reuses `crops::settle_captured_source_snow` in ≤8 slices inside the existing late Snow region. No public shape change: `ActorRuntime`/`ActorAux::Passive`, `FootprintSchedule`, `physics` contracts and `Cargo.toml` stay byte-identical.

**Tech Stack:** Rust1.97.1, existing mornlea_server owners; no dependency, version, protocol, save, Go or native change.

**Spec:** ../design.md and ../specs/rust-authoritative-server/spec.md. This is one passive Snow integration under3.7; nonplayer speed scaling (3.7l3ns0, accepted) is untouched; all other 4.1/4.2 gaps stay open.

## Verified source and chosen owner

Go `passive.go` `advancePassiveMovement`: fresh cows clear the skip flag and `continue` before physics (no sample); grazing cows freeze with a zero input and `continue` before integration (no sample); fallout/invalid cows are `removeAt`-removed before any note (no sample); every other cow integrates once, the home-neighborhood rollback restores the pre-step state (before==after, displacement zero), then `noteSnowFootprint(previous.Position, settled.Position, settled.OnGround)` runs for the surviving cow — after valid native motion and before the caller's passive death settlement in the same phase. `snow_footprint.go`58-89: airborne (`!onGround`) neither accumulates nor clears; `travel += float32(math.Sqrt(float64(dx*dx+dz*dz)))` in f32; threshold0.6 resets travel to0, floors the foot cell with no ground-probe subtraction, suppresses a same-cell resample, remembers the cell even when it is not Snow and not written, and appends at most one dimension+cell candidate. `settleSnowFootprints` drains once per tick in collection order (players by session, then passives by ascending id), fresh silent reads, tier-1 to AIR, no refusal channel.

Rust gap: `step.rs:560` recreates `FootprintSchedule` per tick; `crops::collect_snow_samples` (crops.rs:412-453) re-derives passive rows from `pre_step` with a zeroed per-tick tracker; late collection runs after the passive phase (step.rs:562), so passive stride never accumulates across ticks and pre-death coordinates are unowned. Rejected alternatives: growing `ActorAux::Passive` (public enum, widely constructed); a `BTreeMap` history on the tick context (unbounded, per-tick loan churn); blanket-skipping every `ActorKey::Passive(_)` in `collect_snow_samples` (breaks the qualified legacy fixture contract); an immediate Snow write in the movement pass (moves the source write region). Selected: the private retained book plus a registered-id exclusion, mirroring the accepted `SourcePlayerEntry.snow`/`SourceSnowBatch` semantics (source_player_restore.rs:70-137) without taking over that owner's responsibility. Restart admits residents with no runtime lane and therefore no book occupancy (`admit_residents`, passives.rs:261-285), matching the Go transient discipline.

## Exact private interfaces and algorithms

`PassiveSnowTracker` (passives.rs, module-private) duplicates the accepted `SourceSnowTracker` spelling (source_player_restore.rs:70-108) exactly: `travel: f32, cell: BlockPos, cell_valid: bool`, Copy/Clone/Debug/PartialEq, manual Default zero/ORIGIN/false, and the same preview arithmetic — `dx = after[0]-before[0]`, `dz = after[2]-before[2]` in f32, `(f64::from(dx*dx+dz*dz).sqrt()) as f32`, `travel += distance` in f32; `<0.6` commits travel only; a crossing resets travel to 0, runs `actor_placement::snow_cell(after)?` (checked floors, no ground-probe subtraction), suppresses a same-cell resample, and otherwise remembers the dimensionless cell (even when non-Snow) and yields one candidate.

`pub(crate) struct PassiveSnowBook` in passives.rs, stored by state.rs; manual `Default`; fixed size with no heap in the new book, registration set or settle path (the provider's existing `resident_keys` Vec and other allocations stay as they are):

- `slots: [Option<(PassiveId, PassiveSnowTracker); 32]` — occupancy is the `Option`, never a sentinel id. `note` is lookup-or-insert: a matched occupied slot keeps its tracker (a note never resets an existing id), an absent id inserts a fresh `Default` tracker in the first free `None` slot. Id reuse is handled by an explicit reset event, not by lookup: `insert_spawn` and `admit_residents` reset that id's slot to `Default` at admission, and a bounded reconcile at movement-loop entry forgets slots whose ids are absent from the current residents while their queued candidates survive. A full-table insert with no free slot and no matching id is `Internal{invariant:"passive snow trackers"}` (the existing global passive cap is 32). `PassiveId` is the existing Copy payload of `ActorKey::Passive`.
- `pending: [crops::FootprintCell; 32]`, `len: usize`; `append(dimension, pos)` preflights `len < 32` else `Internal{invariant:"passive snow capacity"}`, prefix preserved on refusal; the append preflight and the checked `snow_cell` precede the tracker commit, so any refusal leaves tracker and prefix byte-exact. No sort/dedup; per-tick collection order is ascending `PassiveId` because `advance_movement` iterates the sorted `resident_keys` order.
- `fn note(&mut self, id, dimension: Dimension, before: [f32;3], after: [f32;3], on_ground: bool) -> Result<(), ServerError>`: `!on_ground` returns Ok with the tracker untouched (airborne neither accumulates nor clears); otherwise the preview above, appending the candidate through the preflight. Home rollback passes before==after (`settled = pose`), so travel gains exactly 0. The fresh skip (passives.rs:586-599), the graze freeze and the quiet-removal path (passives.rs:708-719) all return before `note` is reachable.
- `fn forget(&mut self, id: PassiveId)`: clears only that tracker slot; `pending` candidates survive removal, death and retirement. Called from the movement quiet-removal site and from `settle_deaths` for every staged death record.
- `fn settle_snow(&mut self, context: &mut TickContext<'_>) -> Result<PhaseReport, ServerError>`: refuse `len > 32` with the capacity invariant before any read, then call `crops::settle_captured_source_snow` (crops.rs:518-539) on successive in-order slices of at most 8 (its own `>8` guard never fires on a slice) and sum examined/applied (carried/rejected stay 0); only a fully successful return sets `len = 0`. This reuses the accepted fresh-read transaction (`settle_snow_cell`, crops.rs:545-559) with no parallel Snow transaction and no generic-schedule participation.
- cfg(test)-only `snow_test_snapshot`/`snow_test_state(id)`/`snow_test_set_state(id, ..)` mirror the accepted player helpers (source_player_restore.rs:138-163); they are visible only to lib unit tests, never to integration targets.

Entry split: `pub fn run(ctx, call)` keeps its exact signature and delegates to a new private `fn run_with(ctx, book: Option<&mut PassiveSnowBook>, call) -> Result<PhaseReport, ServerError>`; the `None` path performs no registration and no `note`, so `run` is behaviorally byte-identical for every existing consumer (tests/server_replay/passives.rs:718 and all other callers). `pub(crate) fn run_with_snow(ctx, book: &mut PassiveSnowBook, call)` applies the same shape guard and environment snapshot, then at movement-loop entry — after `advance_spawn`, before the first `advance_movement` — reconciles the book against the current resident ids (admission resets, absent-id forgets, queued candidates retained) and registers EVERY current resident id, including fresh and grazing cows, by calling `ctx.register_native_passive_snow(id)` once per resident key into the fixed bounded 32-entry set; registration precedes every movement pass, so the late generic collector qualifies exactly this tick's actual-owned ids and a newly seen passive can never fall through to duplicate generic collection. The book then threads `Some(book)` through the otherwise unchanged pipeline. Capture integration: `advance_movement` calls `book.note(id, record.dimension, pose.position, settled.position, settled.on_ground)` after the rollback decision and staging, only on the surviving path; the id comes from the already-matched `ActorKey::Passive(id)`. Loan/drop/failure policy: the book is taken from and returned to `AuthorityState` around the context exactly like `source_players`; a failed tick retains accepted candidates and tracker state for the next tick with no motion-rollback claim; dropped/abandoned context loans never touch the book because capture runs only inside the executing tick. Late settle sits after source-player `settle_snow` (players by session) and before `crops::settle_snow_footprints`, reproducing the Go combined players-then-passives order before the remaining generic rows. Exclusion is qualified, not blanket: `collect_snow_samples` skips only registered ids, so unregistered fixture passives keep the legacy path and `FootprintSchedule`'s public directly-constructed behavior is unchanged; if any existing generic crops case stages a passive that this tick-level registration excludes, its expectation update is justified in the same edit and reported to ROOT. No double collection: registered passives never enter `FootprintSchedule.snow_pending`, and passive candidates never enter `SourcePlayerBook.snow_pending`.
