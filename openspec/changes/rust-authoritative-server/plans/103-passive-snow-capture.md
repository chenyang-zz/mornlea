# Passive source Snow capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. OpenSpec tasks.md is the sole status source; the steps below do not create a second checklist.

**Goal:** Retain passive-cow Snow travel/cell memory across actual ticks, capture each surviving cow's sample inside the native movement pass before quiet removal or death settlement, and settle captured original coordinates in the existing late Snow write region after source-player Snow and before legacy generic Snow, with no double collection.

**Architecture:** One module-private fixed-capacity `PassiveSnowBook` (32 tracker slots keyed by `PassiveId`, 32-cell pending batch) is a retained `AuthorityState` field loaned through the tick exactly like the accepted source-player book. Capture is a pure per-actor `note` called from `advance_movement` with the already-held pre-step/settled poses; settlement reuses the accepted `crops::settle_captured_source_snow` transaction in ≤8 slices. No public shape change: `ActorRuntime`/`ActorAux::Passive`, `FootprintSchedule` and `physics` contracts stay byte-identical.

**Tech Stack:** Rust1.97.1, existing mornlea_server owners; no dependency, version, protocol, save, Go or native change.

**Spec:** ../design.md and ../specs/rust-authoritative-server/spec.md. This is one passive Snow integration under3.7; nonplayer speed scaling (3.7l3ns0, accepted) is untouched; all other 4.1/4.2 gaps stay open.

## Verified source and chosen owner

Go `passive.go` `advancePassiveMovement`: fresh cows clear the skip flag and `continue` before physics (no sample); grazing cows freeze with a zero input and `continue` before integration (no sample); fallout/invalid cows are `removeAt`-removed before any note (no sample); every other cow integrates once, the home-neighborhood rollback restores the pre-step state (before==after, displacement zero), then `noteSnowFootprint(previous.Position, settled.Position, settled.OnGround)` runs for the surviving cow — after valid native motion and before the caller's passive death settlement in the same phase. `snow_footprint.go`58-89: airborne (`!onGround`) neither accumulates nor clears; `travel += float32(math.Sqrt(float64(dx*dx+dz*dz)))` in f32; threshold0.6 resets travel to0, floors the foot cell with no ground-probe subtraction, suppresses a same-cell resample, remembers the cell even when it is not Snow and not written, and appends at most one dimension+cell candidate. `settleSnowFootprints` drains once per tick in collection order (players by session, then passives by ascending id), fresh silent reads, tier-1 to AIR, no refusal channel.

Rust gap: `step.rs:560` recreates `FootprintSchedule` per tick, `crops::collect_snow_samples` re-derives passive rows from `pre_step` with a zeroed tracker, and late collection runs after the passive phase, so passive stride never accumulates across ticks and pre-death coordinates are unowned. Rejected alternatives: growing `ActorAux::Passive` (public enum, widely constructed); a `BTreeMap` history on the tick context (unbounded, per-tick loan churn); an immediate Snow write in the movement pass (moves the source write region). Selected: one private sibling of the accepted `SourceSnowBook` on the retained authority, mirroring `SourcePlayerEntry.snow`/`SourceSnowBatch` byte-for-byte in arithmetic and refusal semantics.

## Exact private interfaces and algorithms

`pub(crate) struct PassiveSnowBook` in passives.rs (state.rs stores it; `Default` manual). Tracker is the accepted `SourceSnowTracker` spelling duplicated module-private: `travel:f32, cell:BlockPos, cell_valid:bool`, Copy/Clone/Debug/PartialEq, Default zero/ORIGIN/false.

- `slots: [(PassiveId, PassiveSnowTracker); 32]` with `(PassiveId::default-ish ORIGIN id, Default)` fill; lookup is a bounded linear scan returning `None` when no slot id equals the key — a reused id never inherits prior history even if a removal clear was missed. Insert overwrites the first unmatched/free slot; with the existing passive global cap 32 a full-table insert is `Internal{invariant:"passive snow trackers"}`.
- `pending: [crops::FootprintCell; 32]`, `len:usize`, `append(dimension,pos)` preflights `len<32` else `Internal{invariant:"passive snow capacity"}`; prefix preserved on refusal. Fixed size, no heap, no sort/dedup; collection order is per-tick ascending PassiveId because movement iterates sorted keys.
- `fn note(&mut self, id:PassiveId, dimension:Dimension, before:[f32;3], after:[f32;3], on_ground:bool) -> Result<(), ServerError>`: `!on_ground` returns Ok with tracker untouched (airborne preserves accumulated travel, clears nothing); otherwise the exact accepted preview arithmetic — `dx=after[0]-before[0]`, `dz=after[2]-before[2]` f32, `(f64::from(dx*dx+dz*dz).sqrt()) as f32`, `travel += distance` f32; `<0.6` commits travel only; else travel0, `actor_placement::snow_cell(after)?` (checked floors, no probe), same remembered cell → no candidate; new cell remembered (dimensionless, even non-Snow) and appended. Checked geometry error returns Err leaving tracker/prefix exact. Home rollback passes before==after so travel gains exactly0. Fresh, graze-freeze and quiet-removal paths return before `note` is reachable.
- `fn forget(&mut self, id:PassiveId)`: clears only that tracker slot; `pending` candidates survive removal, death and retirement. Called at the quiet-removal `stage_dead` site (passives.rs:714 region) and at the death-settlement removal site. Restart admits residents with no runtime lane and therefore zeroed trackers (`admit_residents`, matching Go transient discipline).
- `fn settle_snow(&mut self, context:&mut TickContext<'_>) -> Result<PhaseReport,ServerError>`: refuse `len>32` with the capacity invariant, then settle `pending[..len]` by calling `crops::settle_captured_source_snow` on successive ≤8 slices in order and summing examined/applied (its `>8` guard never fires on slices). Only a fully successful return sets `len=0`. This reuses the accepted fresh-read transaction (`settle_snow_cell`) with no parallel Snow transaction and no generic schedule participation.

Capture integration: `advance_movement` calls `book.note(id, record.dimension, pose.position, settled.position, settled.on_ground)` after the rollback decision and after staging, only on the surviving path; `run(context, book, call)` threads the book. Late settle call sits after source-player `settle_snow` (players by session) and before `crops::settle_snow_footprints` (passives by id last), reproducing the Go combined order. Loan/drop/failure policy: the book returns to `AuthorityState` on every exit like the environmental schedules — a failed tick retains accepted candidates and tracker state for the next successful tick without claiming motion rollback; abandoned/dropped context loans never touch the book because capture runs only inside the executing tick. Legacy exclusion: `collect_snow_samples` skips every `ActorKey::Passive(_)` row before the tracker lookup, because every actual passive is native-source owned by the retained tracker; `FootprintSchedule` stays public and its directly-constructed fixture behavior is unchanged. If any existing generic crops case uses a Passive key, update that case's expectation in crops.rs with justification in the same edit; report it to ROOT. No double collection: the actual tick's generic schedule receives no passive rows and passive candidates never enter `snow_pending` of `FootprintSchedule`.
