## Callable signatures and bounds

Public module mornlea_server::core::command_outcome owns:

- CommandDisposition enum (Clone,Copy,Debug,Eq,PartialEq): Unowned; Settled(PhaseReport); Refused(RejectReason). Settled includes accepted deferred work and quiet/stale/no-op reports; only Unowned permits dispatch fallthrough. Refused consumes the envelope without owning a hard error. Result errors stay explicit ServerError and must propagate without conversion.
- CommandResult = Result<CommandDisposition,ServerError>.
- CommandProvider = fn(&mut TickContext<'_>, &CommandEnvelope)->CommandResult, a compile-ready function pointer for real providers and deterministic consumer doubles.
- RejectionStage (Clone,Copy,Debug,Eq,PartialEq): Admission; Settlement. The source's held mining and deferred gameplay rejections use Settlement; ordinary admission uses Admission.
- CommandRejections::try_new(command_limit:usize,player_limit:u8)->Result<Self,ServerError>; permit command_limit0..=4096 and players1..=8. Limits are caller-selected actual drained prefix and current registered-player ceiling, not unbounded incoming queues. Invalid ceilings return Capacity{resource:Commands/Players,limit:4096/8,observed:requested}; player0 returns InvalidInput{field:"rejection_players"}. No allocation required until recording.
- record_command(&mut self,envelope:&CommandEnvelope,reason:RejectReason,stage:RejectionStage)->Result<(),ServerError>: validate SessionKey from original nonzero envelope, fail Internal{invariant:"command rejection session"} on impossible invalid identity. Reserve before mutation, keep exact session/sequence/reason; count all stages against command_limit. Capacity returns Commands with observed=count+1, no append/counter mutation.
- record_held_input(&mut self,session:SessionKey,sequence:u64,reason:RejectReason)->Result<(),ServerError>: always Settlement, count against player_limit, overflow Capacity{resource:Players,limit:player_limit,observed:count+1}, no partial append. Sequence0 is retained, matching existing CommandRejection constructor/source protocol.
- into_events(self)->Vec<RoutedEvent>: consume exactly once, admission insertion order then settlement insertion order; owner-only EventRecipient::Session(session.get()), Event::CommandRejected(CommandRejection::new(sequence,reason)). No sort/dedup/generation replacement; source permits repeated lastInputSequence across distinct ticks.

Store compact private OwnerRejection{session:SessionKey,rejection:CommandRejection} in two Vecs, separate command_count/held_count. Combined length <=command_limit+player_limit <=4104. Lazy capacity grows 8,16,32... capped at this combined bound per lane, using try_reserve_exact before push; allocation failure returns Capacity Commands{limit:combined,observed:total+1} without mutation. At most two compact lane capacities of4104 records (each slot contains only session+sequence+reason, no full Event-sized reserve). into_events materializes at most4104 output events on explicit consumer request; actual tick integration later owns success ordering and recipient queue admission. No disk/network/blocking/locks.
