# Exclusive source tick continuation implementation plan

**Goal:** Suspend a successfully committed source reduction before projection/delivery and complete that same reduction once, while exclusively retaining authority and goal ownership.
**Architecture:** A private state child owns a linear SourceTickContinuation over &mut AuthorityState and &mut SourceGoals. The reducer separates its existing carried/viewer commit from its existing projection/delivery/goals/save tail without changing row order. Current synchronous source advance immediately completes the continuation; ordinary and unpublished final paths keep their existing endpoints.
**Tech Stack:** Rust1.97.1 server reducer/domain/publication/acquisition; existing test-only dispatch hook for explicit trusted controls.
**Spec:** ../specs/rust-authoritative-server/spec.md and ../design.md. Node3.7l3stc; tasks.md owns status. Root executes directly with executing-plans and test-first development under existing full-task authorization.

## Callable continuation and reducer boundaries

New private state child defines pub(crate) SourceTickContinuation<'a> with private authority:&'a mut AuthorityState, goals:&'a mut SourceGoals and reduced:Option<ReducedTick>. No Clone, independent mutable authority exposure, replay constructor, callback provider or unsafe sharing.

AuthorityState::begin_source_tick<'a>(&'a mut self,work:TickBudget,goals:&'a mut SourceGoals)->Result<SourceTickContinuation<'a>,ServerError> performs existing check_source_tick precedence before any reduction, then actual preparation through the trusted fence. Successful begin owns the same goals/authority until terminal completion. SourceTickContinuation::state(&self)->&AuthorityState exposes immutable inspection only; tick(&self)->u64 reads the executing identity. complete(self)->Result<TickPublication,ServerError> consumes the original ReducedTick, runs the existing post-commit tail under the ordinary trusted fence, and only then saturating-bumps the endpoint once. abort(self,error:ServerError)->ServerError consumes the reduction and retains fail_tick(error), with no projection, delivery, capture or counter bump. Drop with reduced still present calls fail_tick(Internal invariant "source tick continuation abandoned"). Completed/aborted owners do not introduce a second failure. Existing first error wins and accepted partial mutations remain owned. A failed complete similarly retains the original hard error without an abandonment replacement.

step::ReducedTick (crate-private, non-Clone) owns tick, original provider events/hits, TickCounters and TickOutcome. prepare_source_tick(state:&mut AuthorityState,budget:TickBudget,goals:&mut SourceGoals)->Result<ReducedTick,ServerError> executes reduction through carried commit, all five moved-owner restorations, source-player pruning and viewer commit; no source projection/reset consumption/delivery/goals.finish_tick/save capture/counter bump. finish_source_tick(state:&mut AuthorityState,reduced:ReducedTick,goals:&mut SourceGoals)->Result<TickPublication,ServerError> executes those exact remaining steps and returns the original publication. Private reduce_tick_to_commit and finish_reduced_tick are reused by reduce_tick_inner; normal/final publish boolean retains current semantics. Shared generic tick_fence catches trusted errors/unwinds and retains existing invariant "authoritative tick panic". Existing source reducer entry remains compatible as a prepare+finish consumer if still used; no unused dead-code suppression is permitted. Remove an obsolete private source-only wrapper when replaced, while preserving public reduce_tick and AuthoritativeFinalReducer.

No global pending phase or ordinary behavior change. The borrow fences external writers while the private continuation is held; normal Drop fences abandonment. This is not a guarantee against intentional std::mem::forget of a private guard; current production consumer always immediately completes it and no external caller can construct one. Future caller ownership and leak policy require their own integration qualification. It is not a lock or boolean. No metadata/save target is selected during suspension by the continuation. Existing ready pages and moved schedules are returned before begin succeeds; counters and persisted outcomes remain uncompleted until the tail succeeds.
