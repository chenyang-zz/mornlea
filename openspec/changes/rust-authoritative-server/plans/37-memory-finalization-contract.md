## Frozen interfaces

- LeaseController implements Clone by cloning its existing Arc<Shared>. Every clone shares lease phase/fence, retained business/control join ownership, capacity, cancellation and close_started. No new controller, HTTP wire, worker or fence is created. Any clone's freeze/close affects all handles. This is the actual provider ownership adapter for MemoryOwner(Box<dyn AgentHandle>) and ShutdownPorts.agent, avoiding independent controllers or a mutex wrapper around blocking lifecycle methods.
- MemoryFinalizer gains required fn pending(&self)->MemoryFinalizationReport. It is a pure snapshot with completed0 and outstanding equal to semantic/request ownership currently retained. MemoryOwner counts distinct companion IDs across reservations, delete_intents, commits, reconciles and deletes, plus pending_retirements.len(); one reservation+its in-flight commit counts once, while a retained cleanup join is separately owned. Failed/malformed deletion remains outstanding after its HTTP record retires. Provider doubles must explicitly implement pending; there is no default zero that could hide work.
- Existing begin_attempt/drain signatures remain. Later finalizer returns nonzero successful reports while still progressing; only actual deadline/fatal refusal is an error. Later shutdown records pending before begin/drain and on errors, and drives repeated drain until zero/deadline. This prerequisite does not claim those behaviors exist.
