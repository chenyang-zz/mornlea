## Selection and progress

Keep existing chunk-only live selection untouched as select_live_chunks. With no actor owner, ordinary select_live calls it exactly as before. With owner enabled, choose preferred group actor/chunk; if it returns empty, try the other group in the same call. Toggle preference only after a nonempty selection, to the other group. Urgent uses existing force/unload eligibility; empty urgent passes do not consume the alternation or starve ordinary actor autosave. Each call returns one family-group cohort, never a new mixed fresh request; the scheduler independently tracks that actual ticket. Actor group uses ledger.select(mode,SaveBudget{chunks:19,estimated_bytes:budget.estimated_bytes}) (16player+three singleton bound), preserving first-whole-record exception. Chunk group retains existing caller count/byte budgets and eight-flight bound. If ledger selection overflows/refuses internally, call fail_tick and return empty, with all earlier held work retained. No new actor clone beyond accepted ledger selection; arbitration has constant overhead. Alternation avoids repeatedly returning the same early actor prefix solely because a combined chunk reservation oversized the cohort.

## Refusal, mixed completions, accounting

return_dirty routes actor keys to the ledger when enabled. An exact target releases/restores force; an unknown/stale identity is ignored. A same-key/revision altered held target calls fail_tick before release. Chunks preserve their existing acquisition release. Manual remember_dirty remains forbidden in live mode.

Enabled actor completion uses a separate private child method; disabled mode preserves the original live chunk completion verbatim. Preflight bounds maximum28unique owners (16players+3singleton actors+8chunks+1metadata); chunk count remains at most8 and player at most16. Overflow is a typed capacity error before mutation. Snapshot keys and committed keys must each be unique; submitted/snapshot lengths and corresponding key/revision must match; every committed identity must be submitted. Bounded Vec key membership replaces any unbounded set construction. Reject every same-key/revision held chunk that fails acquisition.matches before invoking acquisition.validate_saved (that operation deliberately ignores nonmatches). Validate every held chunk with acquisition.validate_saved and every actor with ledger.validate_saved before ANY owner updates. This whole-cohort preflight prevents a forged actor from acknowledging a valid earlier chunk. Metadata remains the existing direct scheduler lane.

After preflight, committed exact targets advance their respective owner; stale/unselected actor/chunk targets are ignored. Failed admitted exact targets remain charged and return in AckReport.retry; never call return_dirty for admitted failure. Incomplete nil-error cohorts remain hard failures. Actor signed-zero/NaN exact identity remains the accepted bitwise ledger contract. Sum ledger/acquisition stats with saturating arithmetic, without scanning clean bodies or materializing chunk views. Frozen key census includes every unique actor/chunk held obligation; retained actor targets remain charged after session retirement even though automatic exit capture/cache policy is not yet supplied.
