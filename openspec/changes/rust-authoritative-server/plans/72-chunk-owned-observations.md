## Exact collection and transformations

New public ChunkBlockObservations derives Clone,Default,Debug,PartialEq; private chunks:BTreeMap<ChunkKey,BTreeMap<(ChunkKey,BlockPos),BlockObservation>>,len:usize. The redundant key in each inner map preserves borrowed full-key iteration without allocation. Empty inner maps never remain. Clone is an explicit off-tick observation operation; production loans move the collection.

Expose only existing consumed operations: new()->Self; len()->usize; is_empty()->bool; get(&self,cell:&(ChunkKey,BlockPos))->Option<&BlockObservation>; insert(&mut self,cell:(ChunkKey,BlockPos),value:BlockObservation)->Option<BlockObservation>; remove(&mut self,cell:&(ChunkKey,BlockPos))->Option<BlockObservation>; values(&self)->impl DoubleEndedIterator<Item=&BlockObservation>; into_values(self)->impl DoubleEndedIterator<Item=BlockObservation>. Implement Index<&(ChunkKey,BlockPos)> with existing missing-key panic behavior, and IntoIterator for &ChunkBlockObservations yielding (&(ChunkKey,BlockPos),&BlockObservation) through Flatten<btree_map::Values<'a,ChunkKey,InnerMap>>. No boxing, dynamic dispatch, allocation or reconstructed keys on reads. Owned into_values consumes inner maps in existing sorted order. Preserve original map semantics even for detached fixtures whose observation fields differ from supplied key.

Add pub(crate) take_chunk(&mut self,key:ChunkKey)->Option<BTreeMap<(ChunkKey,BlockPos),BlockObservation>>: remove the single outer owner; subtract its O(1) len and return it whole. O(log owned chunks), zero per-cell operations; eventual destruction belongs to later retirement policy, not to this method. No record or observation clone, retain-scan, split/append or reconstructed inner map. insert updates len only on absent cell; remove decrements only on actual removal and prunes a now-empty inner owner. Unknown removal/detachment changes nothing.

In state.rs replace exactly ResidentTickState.blocks, AuthorityReadView.blocks and TickContext.blocks types/import plus from_parts construction. All existing get/insert/values/clone/mem::take/field-move callers keep the same logic and exact observation data. Keep CompoundUndo.blocks as its current bounded flat BTreeMap of Option preimages. Replace only its restore_preimages call for context.blocks with a touched-journal loop: Some(original)->insert original; None->remove original key. Generic restore_preimages and other journals remain unchanged. Fixture preload_ready_chunk replaces its old all-cell retain with take_chunk(chunk.key); fixture-only destruction stays on its explicitly off-tick setup path. Existing resident/world snapshots and first-party test consumers compile unchanged through the exact methods/traits above. No global scan/merge added to a tick or altered block-read precedence.
