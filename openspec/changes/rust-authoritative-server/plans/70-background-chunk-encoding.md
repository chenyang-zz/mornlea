1. Each OS loop recv owns exactly one command. Retain a clone of its expected capture token, call operation.encode on the moved supplied owner inside catch_unwind(AssertUnwindSafe(...)), and compare returned capture identity to that expected token before replying. Wrong-token successful result -> Internal{invariant:"chunk encode result"}; panic -> Internal{invariant:"chunk encode owner panic"}. Typed factory refusal propagates unchanged. No authority/current revision/wanted decision occurs here. Send one whole Result through its reply, then take another command. Expected-token clones are O(1); no body clone, disk materialize or duplicate encode. A private injected panic is defensive evidence, not an ordinary codec failure claim.
2. start_encode follows exact packet69 error precedence, monotonic checked ID and8-total ceiling. Append Request retaining the supplied capture; then dispatch free owners. It never builds a codec/extracts/encodes/waits on caller. Queue scans are bounded8. Records include completed-but-unpolled results, so holding results does not release admission capacity.
3. dispatch iterates<=2 owners. For each with requestNone, find the oldest Queued record, create capacity1 reply channel and try_send Command{capture:record.capture.clone(),reply}. Success binds both owner/request and changes Started. Full retains Queued unchanged and stops this dispatch. Disconnected/missing sender -> Complete(Err(Internal{invariant:"chunk encode owner disconnected"})); no CPU job or request loss. Handle reply disconnect the same typed way. No blocking send/channel lock held across CPU work.
4. collect scans<=8 Started records with try_recv. Real result or disconnected reply frees that exact worker.request. If cancelled, remove the whole record/result now; otherwise hold Complete result until its poll. Empty retains all ownership. Index removal does not skip a shifted record. drive collects, dispatches, collects again, returning real completions collected (cancelled collection included).
5. poll_encode calls drive, removes only matching Complete, moves Ready or Failed whole. Unknown/noncomplete/consumed/cancelled -> Pending. No synthetic wakeup, recycled ID, observer copy or delivery of cancelled results. cancel_encode unknownOk; Started only marks cancelled, retaining the record/charge/capture until actual collection; Queued/Complete removes immediately. This lane has<=8 distinct captures plus<=8 held/in-progress prepared outputs,<=2 transient decoded snapshots and<=2 codec scratch owners; extra O(1) capture Arc handles do not create new bodies. Each prepared frame obeys accepted MAX_FRAME_BYTES+5. These are per-lane bounds, not a whole-runtime/RSS claim.
6. stop_new sets stopping. cancel removes every Queued/Complete and marks every Started. wait(deadline) repeatedly drive until queued_jobs0 AND worker_jobs0, even if held completions remain; deadline refusal Timeout{operation:Shutdown} preserves all work/handles. Reuse the accepted generation pause policy: remaining deadline, at most1ms host sleep; lifecycle waits are off tick. close is idempotent ONLY after successful closed; otherwise stop_new, cancel, drain with Timeout{operation:Close}, disconnect all command senders, then for each join wait on is_finished with same bounded pause BEFORE consuming it. Record any join refusal sticky join_failed and return Internal{invariant:"chunk encode owner join"}; never mark closed on failure. Timeout retains unconsumed joins on this same pool for retry. Drop only disconnects senders, never claims joined/cancelled/quiescent completion. No unsafe, global process reap or force kill.
