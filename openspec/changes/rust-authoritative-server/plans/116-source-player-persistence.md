# Source player persistence implementation plan

Goal: retain the latest player state across actual login, settled ticks and disconnect, with cache lookup before disk load and a lossless exit inventory capture. Architecture: the authority owns sixteen cache lifecycle records beside the accepted actor ledger; the ledger remains the only current/save-flight owner. A private state child owns source player preparation, confirmation, capture and retirement. The existing concrete LoginDriver routes cache hits synchronously and actual misses through its borrowed load port. Tech: existing Rust player codec, source restoration, actor projection, crafting repack, Memory/TCP connection core, AutosaveScheduler/background DiskStore. Spec: ../design.md and ../specs/rust-authoritative-server/spec.md. Root uses executing-plans directly; tasks.md owns status.

## Automatic capture and retirement

Private capture_player_saves(&mut self)->Result<(),ServerError> is called once inside the actual reducer after committed settlement, publication and source goal finish, before successful return; it also executes for the actual AuthoritativeFinalReducer. Disabled is a no-op. Healthy Running or Closing allowed, Closed/stickyfailure refused. Iterate only the at-most8 player_slots, direct indexed actor/key lookup, current Active session, source book and runtime/inventory. Active actor or ever_spawned=true is persistable; never-spawned Pending skips observation. project_player uses envelope1 and current fixed overlays, then confirmed session display_name. Observe directly into the unfrozen ledger; no scheduler/disk I/O or body/world census. A projection/ownership refusal stops the tick through its existing sticky fence; prior held captures remain ACK-able.

Retire's enabled preflight runs before changing phase/capacity/source book or dropping any inventory. For an installed actor, rehearse crafting::repack_all on a fixed inventory copy, including all9cells regardless of personal/bench size. Failure is a hard sticky invariant, with session/cache/grid/current save untouched. For a persistable actor, project with the repacked inventory, validate and ledger.observe(value,true,true) before removing source ownership; this preserves Pending-after-death empty inventory and never overwrites never-spawned current. Commit repacked inventory, deactivate/unpin cache and release it only through release_player. A loaded dirty/rewrite, confirmed missing dirty, newer current or selected retry remains cached and charged. Prepared cancellation changes no durable name; unconfirmed Missing disappears completely. Loading cancellation releases only its placeholder. Cache-less preparation failure can still release its session reservation.

After accepted capture, remove that player's physical actor with swap_remove (constant owner transfer), update the moved last player's indexed slot if applicable, and erase only that player's runtime/inventory/mining/view/source/sleep owners. Provider phase order is already sorted by ActorKey; no sibling owns physical vector positions. Current session history/outbox remains with existing transport receipts. This bounds retained player actors independently of historical sessions and does not compact mob history or claim a global memory bound. No capture is permitted after sticky tick failure; reject retirement rather than turn partially reduced state into a durable target. Closing final capture remains available before final selection; never ledger.freeze early.

## Concrete login ticket routing

LiveEndpoint's disabled path continues using provider tickets exactly. Enabled path checks prepare_player_cache before loads.start. Cache Ready creates a logical driver ticket and ready alias with no provider call; a miss starts the actual borrowed PlayerLoadPort and records both logical and original provider tickets. Driver adds next_owned_ticket:u64 (lastissued0), checked increasing logical namespace for enabled requests; Record adds load_ticket:Option<LoginTicket>. Public transport/core receipt carries logical ticket; poll/cancel uses only the optional original provider ticket. Validate duplicate original provider IDs across at-most16aliases before inserting; preserve the older owner and never cancel its ambiguous alias. Preflight logical counter/map collision before provider start, and cleanup any fresh authority reservation on refusal. No mixed logical/provider alias interpretation. Cache-ready cancel needs no load-port cancel. The driver retains accepted provider aliases on refused cancellation as today; stop_new still fences both paths. This is one coherent concrete authority/driver feature, not parallel shared-contract tasks.
