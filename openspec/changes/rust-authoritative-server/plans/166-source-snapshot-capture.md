## APIs and algorithm

Public methods on AuthorityState:

- source_snapshot_identity(&self,key:ChunkKey)->Result<Option<(u64,u64)>,ServerError>; tuple is current Ready generation and physical-owner revision.
- capture_source_snapshot(&self,key:ChunkKey)->Result<Option<ChunkSaveView>,ServerError>; each successful call creates a fresh immutable token over the same current owner; equal key/generation/revision does not imply token equality.

Both share private source_snapshot_ready(&self,key)->Result<Option<&ReadyChunk>,ServerError>. Precedence: existing sticky tick failure unchanged, then phase != Running => InvalidState actualphase, before querying/capturing any key. If acquisition enabled, absent facts or any phase other than Ready => Ok(None), even if a replay fixture retains stale resident bytes. For Ready facts, require matching resident key/generation/base committed revision; missing body or mismatch => Internal invariant "source snapshot ready identity". Unmanaged replay fixtures use resident Ready only; sparse block observations do not establish Ready. For either mode require matching stored key, nonzero generation/revision => InvalidInput chunk_network_snapshot for zero, Internal same invariant for wrong map association. Read no whole set and scan no world.

Identity computes the same successful revision as ReadyChunk::capture, through new checked_pending_revision(drop owner dirty || container owner dirty). The new checked helper returns revision unchanged when neither block nor slots are dirty; otherwise checked_add(1), returning Internal invariant "source snapshot revision" on exhaustion. Existing pending_revision and its existing callers remain unchanged. Both source methods perform this checked calculation before capture, so a new source call cannot reach the legacy expectation panic. This keeps scalar identity and body associated even for prepared replay overlays; ordinary source callers consume it only after successful carried commit. Managed facts compare the resident's base committed revision before this pending calculation, preserving the existing acquisition ledger relation. No new finalization or dirty-state mutation occurs.

Capture calls the existing ReadyChunk::capture with the authority's exact optional drop/container overlays. It shares base/pages by Arc and copies fixed32drop/32furnace/16chest slots; no Ready clone, materialization, cell scan, palette normalization, codec scratch, disk estimate or transport operation. Invalid unchecked block content remains an immutable capture whose actual CPU factory returns Failed chunk_network_snapshot; do not hide it behind persistence payload_estimate None. This surface does not certify session Wanted, observer lifecycle, resync priority, byte selection, tick completion or wire admission.

Rejected alternatives: network_snapshot on caller violates hot-path ownership; capture_chunk_snapshot depends on save scheduling estimates and accepts Unloading; numeric-tuple replacement breaks original token correlation; treating replay Ready maps as managed Ready ignores lifecycle; silently repairing inconsistent managed bodies would conceal an authoritative invariant failure.
