# P12 replay, visual evidence and tooling packets

Read this change's design/delta spec, [strict evidence schema](02-evidence-schema.md) and accepted F1/F3 contract SHAs; authoritative replay also needs accepted F2. `tasks.md` alone tracks status. P12 phase 2 (schema, capture, strict report) precedes P8–P11 candidate evidence; P12 phase 3 reviewed handoff follows those candidates. The controller owns shared CLI entry, scripts dispatcher, producer registry, audit and ledger. No worker edits runtime library, tracked golden image or shared registry. Every new command is prospective until its owner lands it. Each packet begins with a behavioral red, ends with a nonempty focused green and scoped commit, and reports SHA, fixture/hash, discovered/executed count and rollback. Missing identity, required case, data, overflow or I/O is a hard failure; numeric benchmark variance is informational.

## Phase 1: tooling-only contract

**1.1 Inventory and exclusion — controller.** Edit `testdata/visual-golden/producer-registry.json` with only verified current `ui/`, `world/`, `motion/` owners, plus `ledger.md`. Enumerate every tracked case and current producer, existing `scripts/godot/{capture,visual-compare,benchmark}.sh`, `scripts/godot/visual_evidence_contract.py`, `packages/audit/visual_baseline_routing_test.go`, and release exclusions. Reject duplicate/missing owner, unqualified candidate or asset/license gap. Record F1/F3 and applicable F2 SHA. Run `go test ./packages/audit -run VisualBaselineRouting -count=1` and `python3 -m unittest scripts/godot/visual_evidence_contract_test.py` as characterization.

**1.2 Evidence contract landing — controller after 1.1.** Create tooling-only `packages/engine/crates/mornlea_client_core/src/bin/mornlea-migration-evidence.rs`, `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/{schema,mod}.rs`, prospective `packages/engine/crates/mornlea_client_core/tests/migration_evidence.rs` with file-per-node modules, `testdata/runtime-migration/tooling/feature-case-registry.json` and complete valid/invalid CLI fixtures there. Runtime `src/lib.rs` imports none of these modules. Implement exact feature keys, classes, v2 `run.json`, clean-source handoff/release rule, hash/byte/path/required-case checks in 02-evidence-schema. A valid semantic fixture and a missing required GPU case must produce a behavioral red under a permissive double and green under the validator. Run `rustup run 1.97.1 cargo test --manifest-path packages/engine/Cargo.toml -p mornlea_client_core --test migration_evidence --locked -- --list` and `rustup run 1.97.1 cargo test --manifest-path packages/engine/Cargo.toml -p mornlea_client_core --test migration_evidence --locked schema`; require nonzero executed cases and record accepted SHA before capture/report workers.

## Phase 2: parallel capture/report providers, then contract acceptance

**2.1 Registry/schema validator — worker owns `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/registry.rs`, `packages/engine/crates/mornlea_client_core/tests/migration_evidence/registry.rs`; consumes 1.2.** Verify unique case ID, one current canonical owner, required coverage and feature-to-class mapping; candidate never becomes canonical merely by appearing in a run. Test duplicate owner, missing required world/motion case, unknown producer, version mismatch, stale source SHA and valid scoped registry. Run Rust registry filter and `go test ./packages/audit -run VisualBaselineRouting -count=1`.

**2.2a Semantic replay adapter — worker owns `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/semantic.rs` and `packages/engine/crates/mornlea_client_core/tests/migration_evidence/semantic.rs`; after 1.2.** Consume recorded F2/F3/G1 transcript and expected case-set digest; emit one source-bound semantic report with path/hash/byte count per required case before any image request. Test missing case, wrong protocol/descriptor SHA, stale input, failed authoritative replay and valid semantic-only desktop/release case. Run `rustup run 1.97.1 cargo test --manifest-path packages/engine/Cargo.toml -p mornlea_client_core --test migration_evidence --locked semantic`. No Python/GPU edit.

**2.2b No-focus qualified GPU capture — worker owns `apps/mornlea-godot/tests/scripts/migration_gpu_capture.py` and `apps/mornlea-godot/tests/scripts/migration_gpu_capture_check.py`; after 1.2.** Capture UI/world and timed motion cases offscreen without focusing a foreground game window; record per-case renderer/viewport, no-focus proof, dimensions, completion tick or sample timing window, and artifact hash/byte count. Reject dummy headless image as GPU evidence, zero sample, wrong producer, cancellation and stale frame. Run `make godot-python-check`, `make godot-project-check` and `python3 apps/mornlea-godot/tests/scripts/migration_gpu_capture_check.py`. No tracked output.

**2.2c Run orchestrator — worker owns `scripts/godot/migration-evidence.sh`, `apps/mornlea-godot/tests/scripts/migration_capture_check.py` and `packages/engine/crates/mornlea_client_core/tests/migration_evidence/capture.rs`; after 2.2a/2.2b.** Rebuild/identify F3/G1 artifacts, run semantic replay first, dispatch only registry-required GPU/motion cases, write under explicit `build/visual/migration/<feature>` through temporary run directory and atomically finalize after strict validation. Test required semantic-only feature, missing GPU, wrong producer, absent focus isolation, cancelled run, empty output and I/O failure. Run `rustup run 1.97.1 cargo test --manifest-path packages/engine/Cargo.toml -p mornlea_client_core --test migration_evidence --locked capture`, `make godot-python-check`, `make godot-project-check`. No tracked writes.

**2.3 Strict report and comparison — worker owns `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/report.rs`, `packages/engine/crates/mornlea_client_core/tests/migration_evidence/report.rs`; after 1.2.** Validate v2 run schema, accepted contract/registry/case-set hashes, per-case semantic and capture descriptors, and each separate semantic/GPU/difference file sha256 and actual byte count before comparison. Same-producer PNG uses existing thresholds; cross-producer emits semantic agreement plus mandatory path/hash of difference artifact and `cross_producer_review`, never auto-passes review. A required missing/empty/stale/not-comparable case or hard overflow/I/O exits nonzero; semantic-only case may use `not_applicable` only with a passing semantic artifact. Test valid same-producer, cross-producer review-required, changed SHA, zero bytes, missing difference, unsupported dimensions and partial write. Run `rustup run 1.97.1 cargo test --manifest-path packages/engine/Cargo.toml -p mornlea_client_core --test migration_evidence --locked report` and controlled CLI `--feature tooling-fixture --run-dir build/visual/migration/tooling-fixture --strict` with expected success and failure fixtures.

**2.4 Visual-regression dispatcher — controller after 2.1, 2.2c and 2.3; exclusive `scripts/godot/visual-regression.sh`, `scripts/godot/capture.sh`, `scripts/godot/visual-compare.sh`, `testdata/visual-golden/producer-registry.json` and scoped adapter wiring.** For each required case select only current canonical owner; legacy UI/world adapters capture a named case without invoking a full legacy update on Godot-owned baselines. Motion needs a fresh review record, not an image threshold. Test mixed ownership, duplicate/missing owner, unsupported scoped capture and world command that incidentally writes motion. Run full `migration_evidence` suite, a `tooling-fixture` self-test, `scripts/godot/visual-regression.sh --run-dir build/visual/migration/current-owners --strict --feature all --validate-current`, and `go test ./packages/audit -run VisualBaselineRouting -count=1`. The all/current command must discover every required current-owner registry case, not only the fixture. Record phase-2 command/schema acceptance SHA; do not redirect legacy Make targets yet.

## Phase 3: per-case transfer and remaining tools

**3.1 Handoff transaction — worker owns `scripts/godot/migration-handoff.sh`, `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/handoff.rs`, `packages/engine/crates/mornlea_client_core/tests/migration_evidence/handoff.rs`; after 2.4.** Input the versioned per-case reviewed manifest in 02-evidence-schema, binding candidate run/source/artifact/difference hashes, previous owner/hash, next owner, case/registry digest, reviewer and approval record hash. Require clean committed source for handoff; stage complete images+registry outside tracked tree, enumerate side effects, reject anything outside explicit allowlist, verify staged hashes, then publish atomically or restore the entire prior set on failure. Test missing/reused approval, wrong candidate/difference hash, dirty source, world→motion side effect, partial I/O, registry mismatch, repeated invocation and rollback in temporary baseline trees. Run `rustup run 1.97.1 cargo test --manifest-path packages/engine/Cargo.toml -p mornlea_client_core --test migration_evidence --locked handoff` and `go test ./packages/audit -run VisualBaselineRouting -count=1`. Green comparison alone never grants approval.

**3.2 Reviewed case transfer — controller, after relevant P8–P11 clean committed candidate and 3.1.** For each approved case, inspect semantic parity and the exact difference artifact, obtain explicit per-case human approval bound to the candidate/run/difference/previous hashes; record reviewer/approval artifact hash and exact candidate/previous hashes in `ledger.md`, invoke `migration-handoff.sh --manifest <reviewed-file> --run-dir <explicit-dir>`, then run `visual-regression.sh --run-dir build/visual/migration/post-handoff --strict` and `git diff --check`. Without approval the case remains candidate with prior producer. Never run a legacy full-suite writer against mixed ownership. A failed post-handoff check restores the named previous set. This is a serial state transition, not parallel worker work.

**3.3 Benchmark/report collector — worker owns `scripts/godot/benchmark.sh`, `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/benchmark.rs`, `packages/engine/crates/mornlea_client_core/tests/migration_evidence/benchmark.rs`; after 1.2, can overlap other phase-3 providers.** Pin scenario/run/producer identity and sample count, reject truncated/overflow/I/O; report latency/perf values without making variance an exit failure. Test missing sample, wrong producer, overflow counter, valid report. Run `make godot-benchmark` and Rust benchmark filter.

**3.4a Import resource tool — worker after 2.4 owns new `scripts/godot/import-check.sh` and `packages/engine/crates/mornlea_client_core/tests/migration_evidence/import.rs`.** Identify source SHA, producer, asset manifest and target; reject malformed resource, missing hash, cancelled import and output outside explicit build dir. Run import Rust filter and `make godot-project-check`. No CI edit.

**3.4b Developer capture tool — separate worker after 2.4 owns new `scripts/godot/devcapture-check.sh` and `packages/engine/crates/mornlea_client_core/tests/migration_evidence/devcapture.rs`.** Identify source SHA, producer, asset manifest and target; reject empty capture, wrong producer, cancellation and tracked-output path. Run devcapture Rust filter and `make godot-project-check`. No CI edit.

**3.4c Tooling CI integration — controller after 3.4a/3.4b, exclusive `.github/workflows/godot.yml` and new `scripts/godot/tooling-check.sh`.** Invoke both accepted tools with explicit fixture identities, reject zero discovery/malformed resource and preserve optional-only required-entry ownership until P14. Run `scripts/godot/tooling-check.sh`, `make godot-project-check`, `go test ./packages/audit -run 'GodotIsOptionalForLegacyBuild|VisualBaselineRouting' -count=1`.

**4.1 Coverage/guide closeout — controller.** Enumerate all registry cases/producer adapters, record candidate/handoff/rollback and architecture-skill ruling.

**4.2 Stage gate — controller:** `rustup run 1.97.1 cargo fmt --manifest-path packages/engine/Cargo.toml --all --check`, `make godot-python-check`, `make rust-check`, `make dev-check`, `make test-race`, `openspec validate --all --strict --no-interactive` on one SHA. The phase-2 acceptance gate is a real deliverable independent of later feature handoffs; do not mark full P12 complete until phase 3 closes.
