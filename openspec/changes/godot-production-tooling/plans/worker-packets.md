# P12 replay, visual evidence and tooling packets

Read this change's design/delta spec and accepted F1/F3 contract SHAs; authoritative replay also needs accepted F2. `tasks.md` alone tracks status. P12 phase 2 (schema, capture, strict report) precedes P8–P11 candidate evidence; P12 phase 3 reviewed handoff follows those candidates. The controller owns shared CLI entry, scripts dispatcher, producer registry, audit and ledger. No worker edits runtime library, tracked golden image or shared registry. Every new command is prospective until its owner lands it. Each packet begins with a behavioral red, ends with a nonempty focused green and scoped commit, and reports SHA, fixture/hash, discovered/executed count and rollback. Missing identity, required case, data, overflow or I/O is a hard failure; numeric benchmark variance is informational.

## Phase 1: tooling-only contract

**1.1 Inventory and exclusion — controller.** Edit `testdata/visual-golden/producer-registry.json` with only verified current `ui/`, `world/`, `motion/` owners, plus `ledger.md`. Enumerate every tracked case and current producer, existing `scripts/godot/{capture,visual-compare,benchmark}.sh`, `scripts/godot/visual_evidence_contract.py`, `packages/audit/visual_baseline_routing_test.go`, and release exclusions. Reject duplicate/missing owner, unqualified candidate or asset/license gap. Record F1/F3 and applicable F2 SHA. Run `go test ./packages/audit -run VisualBaselineRouting -count=1` and `python3 -m unittest scripts/godot/visual_evidence_contract_test.py` as characterization.

**1.2 Evidence contract landing — controller after 1.1.** Create tooling-only `packages/engine/crates/mornlea_client_core/src/bin/mornlea-migration-evidence.rs`, `src/bin/migration_evidence/{schema,mod}.rs`, prospective `tests/migration_evidence.rs` with file-per-node modules, and one CLI fixture under `testdata/runtime-migration/tooling/`. Runtime `src/lib.rs` imports none of these modules. Strict CLI accepts `--feature <registered-key> --run-dir <explicit-path> --strict`; no implicit latest run, tracked output or network. `run.json` contains `{schema_version:1,run_id,feature,source_sha,worktree_state,producer_id,contract_versions,scenario_id,input_sha256,asset_manifest_sha256,runtime_id,platform:{os,arch},capture:{kind,completion_tick,width,height},budgets:{messages,meshes},cases:[{case_id,class,required,semantic_status,artifact_path,sha256,byte_count,sample_count,comparison_status}]}`. Require all nonempty identity fields and positive case/sample counts; paths are run-relative without `..`/absolute paths. `class` is only `ui|world|motion`; `semantic_status` is `pass|fail`; `comparison_status` is `same_producer_pass|cross_producer_review|failed|not_comparable`. Required `not_comparable` fails strict acceptance. Contract test double supplies one valid and one missing required case and must behaviorally reject the latter. Run `cargo test ... -p mornlea_client_core --test migration_evidence --locked -- --list` and schema filter. Record accepted SHA before capture/report workers.

## Phase 2: parallel capture/report providers, then contract acceptance

**2.1 Registry/schema validator — worker owns `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/registry.rs`, `packages/engine/crates/mornlea_client_core/tests/migration_evidence/registry.rs`; consumes 1.2.** Verify unique case ID, one current canonical owner, required coverage and feature-to-class mapping; candidate never becomes canonical merely by appearing in a run. Test duplicate owner, missing required world/motion case, unknown producer, version mismatch, stale source SHA and valid scoped registry. Run Rust registry filter and `go test ./packages/audit -run VisualBaselineRouting -count=1`.

**2.2 Semantic replay/capture orchestrator — worker owns `scripts/godot/migration-evidence.sh`, `apps/mornlea-godot/tests/scripts/migration_capture_check.py`, `packages/engine/crates/mornlea_client_core/tests/migration_evidence/capture.rs`; consumes 1.2.** Rebuild/identify F3/G1 artifacts, run semantic replay first, then request no-focus qualified GPU capture for `ui`/`world` and timed motion samples. Write only under the explicit `build/visual/migration/<feature>` run dir; first write to a temporary run dir and atomically finalize after completion boundary. Dummy headless render yields semantic/lifecycle evidence only. Test absent focus isolation, dummy GPU image rejected, empty output, cancelled run, wrong producer, 0/one samples and I/O failure. Run Rust capture filter, `make godot-python-check`, `make godot-project-check`. No tracked writes.

**2.3 Strict report and comparison — worker owns `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/report.rs`, `packages/engine/crates/mornlea_client_core/tests/migration_evidence/report.rs`; consumes 1.2.** Validate run schema, sha256 and actual file byte count before comparison; same-producer PNG uses existing thresholds, cross-producer emits semantic agreement plus explicit difference artifacts and `cross_producer_review` status, never auto-passes review. A required missing/empty/stale/not-comparable case or I/O error exits nonzero. Test valid same-producer, valid cross-producer review-required, changed SHA, zero bytes, missing file, unsupported dimensions and partial write. Run Rust report filter and controlled CLI `--feature tooling-fixture --run-dir build/visual/migration/tooling-fixture --strict` with both expected 0 and expected nonzero fixture invocations.

**2.4 Visual-regression dispatcher — controller after 2.1–2.3; exclusive `scripts/godot/visual-regression.sh`, scoped producer adapters and registry wiring.** For each required case select only the current canonical owner; legacy UI/world adapters must capture a named case without invoking full legacy update on Godot-owned baselines. Motion cases require fresh human review record, not an image threshold. Test mixed ownership, duplicate/missing owner, unsupported scoped capture and world command that incidentally writes motion. Run full `migration_evidence` suite, `scripts/godot/visual-regression.sh --run-dir build/visual/migration/tooling-fixture --strict`, audit visual routing. Record phase-2 command/schema acceptance SHA. Do not redirect legacy Make targets yet.

## Phase 3: per-case transfer and remaining tools

**3.1 Handoff transaction — worker owns `scripts/godot/migration-handoff.sh`, `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/handoff.rs`, `packages/engine/crates/mornlea_client_core/tests/migration_evidence/handoff.rs`; after 2.4.** Input reviewed manifest `{case_id, candidate_run_id, candidate_sha256, previous_owner, next_owner, expected_diff, reviewer, approval_record, rollback_manifest_sha256}` for every touched file. Stage complete images+registry outside tracked tree, enumerate side effects, reject anything outside approved allowlist, verify staged hashes, then publish atomically or restore entire prior set on any failure. Test unapproved write, world→motion side effect, partial I/O, registry mismatch, repeat invocation and rollback. Use temporary baseline trees only; run Rust handoff filter and `go test ./packages/audit -run VisualBaselineRouting -count=1`. The script cannot infer approval from a green comparison.

**3.2 Reviewed case transfer — controller, after relevant P8–P11 candidate and 3.1.** For each approved case, inspect semantic parity/differences and obtain explicit per-case human approval; record reviewer/approval and exact candidate/previous hashes in `ledger.md`, invoke `migration-handoff.sh --manifest <reviewed-file> --run-dir <explicit-dir>`, then run `visual-regression.sh --run-dir build/visual/migration/post-handoff --strict` and `git diff --check`. Without approval the case remains candidate with prior producer. Never run a legacy full-suite writer against mixed ownership. A failed post-handoff check restores the named previous set. This is a serial state transition, not parallel worker work.

**3.3 Benchmark/report collector — worker owns `scripts/godot/benchmark.sh`, `packages/engine/crates/mornlea_client_core/src/bin/migration_evidence/benchmark.rs`, `packages/engine/crates/mornlea_client_core/tests/migration_evidence/benchmark.rs`; after 1.2, can overlap other phase-3 providers.** Pin scenario/run/producer identity and sample count, reject truncated/overflow/I/O; report latency/perf values without making variance an exit failure. Test missing sample, wrong producer, overflow counter, valid report. Run `make godot-benchmark` and Rust benchmark filter.

**3.4a Import resource tool — worker after 2.4 owns new `scripts/godot/import-check.sh` and `packages/engine/crates/mornlea_client_core/tests/migration_evidence/import.rs`.** Identify source SHA, producer, asset manifest and target; reject malformed resource, missing hash, cancelled import and output outside explicit build dir. Run import Rust filter and `make godot-project-check`. No CI edit.

**3.4b Developer capture tool — separate worker after 2.4 owns new `scripts/godot/devcapture-check.sh` and `packages/engine/crates/mornlea_client_core/tests/migration_evidence/devcapture.rs`.** Identify source SHA, producer, asset manifest and target; reject empty capture, wrong producer, cancellation and tracked-output path. Run devcapture Rust filter and `make godot-project-check`. No CI edit.

**3.4c Tooling CI integration — controller after 3.4a/3.4b, exclusive `.github/workflows/godot.yml` and new `scripts/godot/tooling-check.sh`.** Invoke both accepted tools with explicit fixture identities, reject zero discovery/malformed resource and preserve optional-only required-entry ownership until P14. Run `scripts/godot/tooling-check.sh`, `make godot-project-check`, `go test ./packages/audit -run 'GodotIsOptionalForLegacyBuild|VisualBaselineRouting' -count=1`.

**4.1 Coverage/guide closeout — controller.** Enumerate all registry cases/producer adapters, record candidate/handoff/rollback and architecture-skill ruling. **4.2 Stage gate — controller:** `rustup run 1.97.1 cargo fmt --manifest-path packages/engine/Cargo.toml --all --check`, `make godot-python-check`, `make rust-check`, `make dev-check`, `make test-race`, `openspec validate --all --strict --no-interactive` on one SHA. The phase-2 acceptance gate is a real deliverable independent of later feature handoffs; do not mark full P12 complete until phase 3 closes.
