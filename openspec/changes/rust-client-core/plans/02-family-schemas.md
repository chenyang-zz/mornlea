# F3 typed C1/C2 family and capacity packet

This packet is controller-owned input to F3 1.2. The prospective `mornlea_client_core` crate does not exist. The controller must reconcile the accepted F1 protocol/domain registry and F2 S2 identity, land compiling declarations plus one behavioral consumer double, then record the contract SHA. Workers implement projections only against that SHA. Missing supported variants, limits or exact imports block dispatch; they are not worker design decisions.

## C1 semantic ingress and bounded queues

`InputBatch {epoch: SessionEpoch, actions: Vec<ClientIntent>}` has 0..=128 semantic actions; check length and every action before queue/journal allocation, local sequence increment or outbound enqueue. An empty semantic batch returns `InputReceipt::Noop`, reserving no bytes or sequence. The P11 device-event adapter separately converts an empty device frame into one neutral semantic `PlayerInput`, preserving Go pilot per-frame control behavior. `ClientIntent` is the closed F1 domain command set plus separate chat: `PlayerInput(PlayerControl)`, `PlaceBlock(PlacementIntent)`, `Resync(ResyncIntent)`, `SelectHotbar(HotbarSlot)`, `OpenContainer(LookAngles)`, `TillSoil(LookAngles)`, `BoneMeal(LookAngles)`, `CollectWater(LookAngles)`, `PlaceWater(LookAngles)`, `MoveInventory(InventoryMove)`, `MoveCrafting(CraftingMove)`, `MoveContainer(ContainerMove)`, `CloseContainer`, `DropSelectedItem`, `TakeCraftingOutput`, `EquipArmor`, `MovePartial(PartialMove)`, `QuickMove(StackSource)`, `DropStack(StackSource)`, and `Chat(ChatIntent)`. The controller matches these against the accepted F1 `Command`/`PlayIntent` registry at 1.2; any new accepted discriminant requires a contract revision before dispatch. `KeepAliveReply` is generated by the session control path, never by a UI input batch. The held primary bit is `PlayerControl.actions().primary`; authority chooses mining, combat or no action from that bit and the current target. There is no fabricated separate mining wire command. Device key/button/pointer events and focus policy are P11/P10 adapters that produce these semantic actions. `InputBatch` never contains a keyboard scan code or borrowed Godot object. A valid local receipt is admission, not server confirmation.

`ContainerToken {epoch: SessionEpoch, reference: ContainerRef, confirmed_revision: ConfirmedRevision}` and `ContainerOperation` are F3-owned checked types. `ContainerRef` is the accepted F1 typed kind/dimension/location/generation reference; the confirmed revision is client mirror attribution, not a new wire field. `InputTranslator::validate_batch(&InputBatch, &ConfirmedMirror, &ClientLimits) -> Result<ValidatedInputBatch, ClientError>` checks session phase/epoch, finite/ranged control values, every target/slot/text and current container token/revision, and precomputes encoded records/bytes plus journal slots. It does not mutate any owner. `Chat` uses F1 `PlayIntent::Chat`, needs queue bytes/record but no local sequence or prediction journal entry; `KeepAliveReply` is a session-only control reply. `InputAdmissionState` is the C1-owned mutable borrow of outbound queue, prediction journal and next sequence. `InputTranslator::commit(ValidatedInputBatch, &mut InputAdmissionState) -> Result<InputReceipt, ClientError>` checks all queue/journal capacity, checked next contiguous sequence range for only F1 `PlayIntent::Sequenced` actions and allocation reservations before changing any of the three owners. It appends all records/journal entries and advances the sequence in one single-owner critical section; a mixed batch commits or rejects atomically. It returns `Noop` for an empty semantic batch; otherwise `Queued {epoch, first_sequence: Option<u64>, sequenced_count, chat_count}`, where `first_sequence` is `None` exactly when there are no sequenced actions. Duplicate sequence, closed container, stale token and a full queue leave the mirror, sequence and queue unchanged. P10 calls this accepted path through G1; it does not duplicate token authority in another Rust module.

`ClientLimits::try_new` accepts the private fields in [00-client-contract.md](00-client-contract.md) and exposes read-only accessors. `ClientWorkBudget::try_new(messages: u16, meshes: u16)` allows zero and caps each at 4096. Recheck both values at `step` before dequeue. One decoded inbound observation counts as one record; its owned body bytes count toward `inbound_bytes` after the v45 2 MiB frame cap is checked. One encoded outbound command counts toward `outbound_commands` and `outbound_bytes`. A prediction journal entry counts once per accepted local sequence, up to the measured ceiling (pilot 256); a full journal returns `Capacity` before outbound admission. Preparation results are separately bounded and never dropped after acceptance; an obsolete epoch/generation result is counted as stale upon drain. `step` drains up to its work budget and retains the FIFO remainder. A capacity error never coalesces command, removal, durable acknowledgment or disconnect records. The controller measures all queue high-water and encoded byte maxima on every supported 1.1 replay; proposed 4104/8 MiB/4096 values may change only before the contract SHA is frozen.

`connect` uses an injected monotonic clock. The shared S2 hello/login deadline policy is 5 s/10 s unless the accepted F2 contract changes it. Expiry yields one terminal `Timeout` observation, releases transport resources once and rejects late login. Memory and TCP feed the same validated observation queue and transcript. `ConfirmedRevision` is a client-issued revision for one complete accepted authoritative observation, not a fabricated server tick; zero is reserved for pending-connection local/session frames before the first complete server observation. A server packet without tick, including `ForgetChunks`, has `source_tick: None`; order comes from accepted transport sequence and mirror application. A duplicate, backward, malformed or old-epoch observation leaves the previous mirror and frame intact.

## Common family header, identity and bytes

The controller defines `FamilyKey {logical_name: &'static str, major: u16, minor: u16}`, `RecordHeader {epoch: SessionEpoch, revision: ConfirmedRevision, source_tick: Option<u64>, operation: FamilyOperation}`, and `FamilyOperation::{Upsert,Remove}`. An item identity is `(epoch, family_key, dimension when present, kind when present, stable_id)`; a reused stable ID requires an ordered `Remove` in the same or prior accepted revision. `RecordHeader` is owned and checked even when a frame parent has the same epoch/revision. All positions are finite `f64` world blocks, velocities finite blocks/tick and angles finite radians. Integer dimensions, sections, chunk coordinates, slot indices and generations are typed wrappers; no sentinel zero means `None`. Every collection has a checked length before allocation. Text limits are copied numerically from the accepted F1 packet/domain registry into `contracts.rs` at 1.2, with an explicit maximum UTF-8 byte count per field; if a field has no accepted bound, 1.2 blocks until the controller defines and replays a compatible cap.

`PresentationFrame::validated_size()` uses checked addition over fixed scalar fields, all record headers, enum tags, UTF-8 bytes, vector elements, optional tags and opaque prepared-resource keys. It counts the **entire owned payload** once per family and once per frame, never just GPU bytes or an ABI pointer. The frame validator rejects a family count above the measured ceiling and a total above the measured frame cap before one `Arc` swap. The pilot's maximum world batch is 4,325,408 bytes; 4 MiB is therefore not a valid parity cap. The proposed 8 MiB cap is accepted only after 1.1 proves all supported aggregate frames fit. A malformed family, mixed revision, duplicate required family, invalid number or byte overflow preserves the previously visible frame and `frame_index`. Unknown optional minor-version fields are skipped using their declared byte length; a missing required field, higher unsupported major or too-new required minor rejects before feature creation. Numeric G1 IDs are assigned only by F3 3.1; pilot IDs 1..8 remain a different producer identity. `ActorId` is a closed tagged union of accepted F1 `PlayerId`, `DropId`, `HostileId`, `PassiveId`, `ProjectileId` and `CompanionId`; the tag must match `ActorRecord.kind` and preserves each source identity without numeric conversion. `ActorDimension` is `Known(Dimension)` for typed F1 actor dimensions or `DropRaw(i32)` for the accepted `DropId` dimension, which F1 deliberately leaves open; no unknown drop dimension is silently coerced to a known world.

The detail tag must match `kind`; `None` is legal only for a packet with no additional actor fields. `PassiveDespawnReason` maps exactly the accepted vanished/died wire enum. A visual animation may interpret these observations, but C2 does not invent an actor attack, projectile hit, companion death or passive lure marker.

A state/despawn packet without a dimension is matched to exactly one live confirmed mirror identity; an orphan, ambiguous or old-generation packet is rejected and counted. F1 `f32` positions/angles/velocities convert exactly to finite `f64` values without inventing absent components. The drop geometry helper and every detail variant must compile in F3 1.2 before the six actor workers start; if the accepted F1 helper cannot express `block_index`, the controller revises the schema instead of allowing a worker guess.

The `actors@1` family is implemented as disjoint per-kind projections followed by one serial assembler. `inventory-ui@1` and `world-ui@1` use the same pattern. Their assemblers sort by confirmed source order, then stable identity, with `Remove` before reuse. They reject duplicate record keys and over-limit totals. F3 1.2 predeclares and registers every per-kind module and test entrypoint; no worker changes `lib.rs`, `mod.rs`, `frame.rs`, a registry or family assembler outside its assigned node.

## Audio provenance and dedup

`CueProvenance` is closed to `Confirmed {observation: ObservationKey, authoritative_event_id: Option<u64>}`, `Predicted {input_sequence: u64}`, and `Local {local_event_sequence: u64}`. `ObservationKey {epoch, confirmed_revision, ordinal}` is assigned only after a complete accepted observation; it exists even when the server packet has no universal event ID. Confirmed cues dedup on `(epoch, authoritative_event_id, cue_id)` when the ID exists, otherwise `(ObservationKey, cue_id)`. Predicted cues dedup on `(epoch, input_sequence, cue_id)` across correction replay; rejected input cancels its pending predicted cue. Local UI cues dedup on `(epoch, local_event_sequence, cue_id)` and never claim server confirmation. Only footsteps/snow movement use predicted provenance, local UI click uses local provenance, and combat/place/world outcome cues use confirmed provenance, avoiding an unsupported cross-class correlation. Reset clears epoch-scoped keys; absence of an audio device does not alter record generation. Tests use an authoritative chat event with ID, a combat/place packet without one, predicted snow step and local UI click; duplicate/replay and reset cases must retain the declared counts.

## Required contract examples and dispatch gate

The 1.2 consumer double must run these cases after a behavioral red: a valid `ForgetChunks` yields `source_tick: None` and ordered remove; a valid 4,325,408-byte pilot-sized world batch is below the accepted measured frame cap; one byte over the accepted cap rejects with old frame/index intact; mixed revision rejects; a mixed batch of sequenced input/chat/input commits exactly two contiguous local sequences and one unsequenced chat; chat-only returns `first_sequence: None`; empty semantic batch is `Noop`; 128 sequenced actions commit one contiguous sequence range, while action 129, stale container token and full prediction journal commit none; a confirmed cue lacking event ID dedups by `ObservationKey`; an unknown optional minor field is skipped, while incompatible major/required minor fails. The ledger records exact F1 packet source, numeric text/record/byte limits, case fixture digest and accepted SHA. Family workers cannot start until these declarations and tests compile and pass; feature workers additionally require the G1 descriptor SHA.
