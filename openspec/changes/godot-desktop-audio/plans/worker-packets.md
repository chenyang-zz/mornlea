# P11 desktop audio, input and lifecycle packets

Read this change's design/delta spec and accepted F3 `audio-cues@1`, `input@1`, `lifecycle@1` and G1 descriptor SHA. `tasks.md` is the only status source. Rust client-core cue selection and dedup are F3 ownership and read-only here; embedded Python/Godot owns device presentation. The controller owns shared test entrypoints, `feature.tres`/catalog, harness runner, asset manifest and ledger. Workers edit only named modules/scripts, add a behavioral red first, then real green; each reports SHA, fixture digest, nonzero test count, exact no-device/overflow behavior and rollback. No automated test focuses a foreground game window; manual real-device acceptance needs explicit user request.

**1.1 Cue/device inventory — controller.** Edit `testdata/runtime-migration/client/desktop-cases.json` and `ledger.md`. Enumerate current `packages/client/audio/cue.go` cue triggers, source event IDs, spatial/non-spatial, category, asset hashes and current Go input/focus lifecycle cases. Bind each to F3 record and P11 test; missing licensed required asset or descriptor blocks activation. Record per-target macOS/Windows/Linux status independently. Run `go test ./packages/client/audio -run Cue -count=1` and `make godot-input-check` for characterization.

**1.2 Harness registration — controller.** Create prospective `packages/engine/crates/mornlea_client_core/tests/desktop_contract.rs`, file-per-node modules, `scripts/godot/audio-check.sh` and `apps/mornlea-godot/tests/scripts/desktop_contract_check.py`. A fake device deliberately plays the same event twice to obtain behavioral red; real F3 dedup and adapter must green. Require nonzero discovery in `cargo test ... -p mornlea_client_core --test desktop_contract --locked -- --list` and `scripts/godot/audio-check.sh --self-test`.

**2.1 Cue-to-resource mapping — worker owns `apps/mornlea-godot/platform/desktop/audio/cue_map.py`, `tests/scripts/desktop_cue_map_check.py`; read F3 cue and 1.1 asset inventory.** Resolve only manifest-listed hashed cue IDs to Godot resource keys; validate category, finite position, volume/pitch range and resource availability before playback. Unknown optional cue is counted/suppressed, missing required asset fails activation. Test known spatial/non-spatial cue, unknown ID, wrong hash, invalid gain and reset. Run `scripts/godot/audio-check.sh`, `make godot-asset-check`, `make godot-python-check`. Do not change cue semantics or invent fallback sound.

**2.2 Audio playback adapter — worker owns `apps/mornlea-godot/platform/desktop/audio/desktop_audio_feature.py`, `tests/scripts/desktop_audio_check.py`; after 2.1.** Consume ordered `audio-cues@1` once by `(epoch,event_id,cue_id)`; fake/no-device consumes semantic cue without later replay burst; stop/release channels on deactivate on the Godot thread. Test duplicate event, no device then restored device, volume change, source despawn, callback after reset and 4096/4097 family records. Run `scripts/godot/audio-check.sh`, `make godot-python-check`, `make godot-project-check`. Do not open a real device in deterministic tests.

**2.3 Desktop input — worker owns `apps/mornlea-godot/platform/desktop/input/desktop_input_feature.py`, `apps/mornlea-godot/tests/scripts/desktop_input_check.py`; read F3 input.** Translate keyboard/mouse/controller focus events to whole typed `InputBatch`, emit release for held actions on focus loss/disconnect, reject a batch beyond 128 events without partial enqueue. Test press/release, controller unplug, focus loss while moving, pointer invalid ray, 128/129, repeated reset. Run `make godot-input-check`, `make godot-python-check`, `make godot-smoke`. No direct server/world mutation.

**2.4 Device lifecycle — worker owns `apps/mornlea-godot/platform/desktop/lifecycle/desktop_lifecycle_feature.py`, `apps/mornlea-godot/tests/scripts/desktop_lifecycle_check.py`; read G1 lifecycle.** Maintain generation token for callbacks; release device subscriptions/audio channels/input state before native handle close. A callback with an old generation is ignored and counted, not applied. Test activate→reset→deactivate, double deactivate, callback after close, optional audio failure preserving session and 100 no-device cycles. Run `scripts/godot/audio-check.sh`, `make godot-input-check`, `make godot-python-check`.

**3.1 Serial assembly and transcript parity — controller after 2.1–2.4.** Exclusive desktop feature manifests/catalog, `tests/desktop_contract/integration.rs` and shared harness wiring. Negotiate symbolic audio/lifecycle requirements through G1 before activation; consume real F2→F3 cues and typed input through Godot fake devices. Compare event/dedup/focus sequence to 1.1 Go transcript, assert zero stale callbacks and complete teardown. Run full desktop Rust target, `scripts/godot/audio-check.sh`, `make godot-input-check`, `make godot-smoke`. Missing physical device does not erase semantic outcome.

**3.2 Target qualification — controller after 3.1.** On each actual supported target run the same fake/no-device audio and input suite, record OS/toolchain/runtime/asset identity and real-device status separately. `macos`, `windows`, `linux` reports cannot substitute for one another; unavailable target remains open. Real-device manual acceptance is separate and only when explicitly authorized. Run Rust desktop target and `scripts/godot/audio-check.sh`/`make godot-input-check` on each target.

**3.3 Candidate evidence — controller after 3.1 and P12 phase 2.** Run `scripts/godot/migration-evidence.sh --feature desktop --run-dir build/visual/migration/desktop --strict` and audit `VisualBaselineRouting`; record semantic cue/input trace and any visual candidate with producer/capture identity. Keep candidate untracked; P12 reviewed per-case handoff alone may change canonical owner.
