# Frozen storage corpus contract

This packet is normative for nodes 1.1–5.1. It describes test evidence, not a production save format. A worker that finds an incompatible Go or Rust API stops that node and gives the controller a failing example; it does not invent another envelope, error category, source owner or migration rule. Existing `testdata/runtime-migration/contracts.json` keeps schema version 2 and its unrelated cases.

## Case row and operation

Each storage `CaseSpec` has `id=save.<family>/<supported-version>/<operation>/<label>`, `family`, `version`, `operation`, `arguments`, `input`, `input_format:"binary"`, `expected`, `checkpoints:["0"]`, and `rust_consumer:"mornlea_storage"`. The `arguments` member is added to Go `CaseSpec` as `json.RawMessage` with `json:"arguments,omitempty"`; its decoded value must be one JSON object, at most 1,024 bytes, with no duplicate or unknown keys. The existing Rust loader already retains this member as `FrozenCase.arguments`. `packet_key` is absent. `encoded` is required for a successful exact-byte encode and for chunk's successful logical-byte encode, and absent on errors and decode/order cases. Its path is a reviewed binary asset. A save case is executable only when its `(family,version,operation)` is registered in the Go consumer registry and exercised by the Rust dispatcher. The route is `decode` for reads, `encode` for current writes, and `order` only for region bank selection; `order` is already an allowed manifest operation.

The input asset is **the raw save byte sequence**, never an invented binary wrapper. For `decode`, use it directly. For `encode`, first decode the input with the exact family arguments to obtain a valid constructed current DTO, then call the Go or Rust current writer; a historical player input may therefore have `version:"9"` on its encode route while the bytes themselves carry an older schema. Decode failures are separate `decode` cases. Invalid constructed DTOs are covered by the named writer unit tests, since invalid DTOs cannot be recovered from a valid input record. A short-capacity `encode` case uses a valid input and derives its expected `needed` from Go's successful canonical encode length. Region `order` concatenates exactly two 28,672-byte bank images as bank A then B; decode each with the same key/file-size and pass both success/error results to the selector. No test uses a live store or a file path as a save input.

| Family | Exact `arguments` keys | Go/Rust dispatch |
| --- | --- | --- |
| `save.player` | `requested_player_id`: 32 lowercase hex digits for the 16 UUID bytes; optional `capacity`: unsigned integer | `player.Decode` / `decode_player` with requested ID; encode decodes source first and calls current writer |
| `save.chunk` | `dimension`, `x`, `z`: signed 32-bit integers; `revision`: unsigned decimal **string**; no `capacity` in corpus cases | `chunk.Decode` / `decode_chunk` with `ChunkKey` and requested revision; encode decodes source first |
| `save.region` | `dimension`, `x`, `z`: signed 32-bit; `file_size`: signed decimal **string**; `component`: `"bank"`, `"superblock"` or `"banks"`; optional `capacity` | bank calls `DecodeRegionBank` / `decode_region_bank(key,bytes,file_size)`; superblock calls `DecodeSuperblock` / `decode_superblock(key,bytes)`; banks requires operation `order` and calls `SelectRegionBank` / `select_region_bank` on two decode results |
| `save.world-metadata`, `save.hostile`, `save.passive`, `save.companion` | Empty object `{}`; optional `capacity` only on `encode` | Corresponding pure `Decode`/`Encode` or private metadata `decodeMetadata`/`encodeMetadata`, and corresponding Rust crate-root codec |

`capacity` is permitted only on **non-chunk** `encode`; it is an unsigned integer no larger than the Go canonical output length and means a caller output slice of exactly that size. The structural inventory validator checks only its JSON type and u32 range; the Go producer checks it against the real Go encoded length and the Rust dispatcher against Rust preflight length. Chunk compressed lengths can differ across Go/Rust zstd implementations, so chunk corpus rows forbid `capacity`; node 4.2 tests Rust frame N-1/N/N+7 and `OutputTooSmall` locally against that encoder's own length. Omission means exact required size for byte-exact families. To test N+7 suffix preservation use writer unit tests, not a corpus argument. Region `component:"superblock"` is permitted only for `decode` or `encode`, `"bank"` for `decode` or `encode`, and `"banks"` only for `order`. The registry includes `save.region/1/order` once its selection test executes. For `order`, the `file_size` value applies to both bank decoders; for superblock it is present for a uniform region argument shape but unused. `encode` derives a bank from a successful decode of input bytes, or a superblock key from its successful validation, before writing. Unsupported declared save versions live inside input bytes while the manifest route uses a supported version; a future or version-zero negative therefore does not invent an unsupported route.

`validateCaseSpecConsumer` rejects a storage row with wrong keys/types/operation/component, an input >4 MiB, a nonzero or extra checkpoint, wrong `encoded` presence, duplicate case ID or missing route. It remains a structural, stdlib-only validator and does not decode save bytes or infer encoded lengths. For a **successful `decode` case only**, each Go family producer and Rust dispatcher checks that the input's actual schema equals case `version`; after the codec has accepted the input, read its little-endian u32 schema at bytes 4..8 for region/metadata and 8..12 for player/chunk/hostile/passive/companion. Never use those raw bytes to declare an invalid input successful. A malformed-version negative is placed on the current supported route and has a label beginning `invalid-version-`. For `encode`, `version` names the required **output** current schema; an older decoded input is permitted only for the player migration case, and both sides decode the emitted output and assert that current schema plus the documented rewrite state. Go and Rust dispatch both independently check the same argument table and exact input lengths. Malformed corpus metadata is a harness failure, not a codec `Corrupt` observation.

## Expected result and complete value comparison

Expected JSON is exactly one of:

```json
{"kind":"ok","category":"save","value_sha256":"sha256:<64 lowercase hex>","length":78}
{"kind":"ok","category":"save","value_sha256":"sha256:<64 lowercase hex>","logical_length":196608}
{"kind":"error","category":"corrupt"}
{"kind":"error","category":"future_version"}
{"kind":"error","category":"output_too_small","needed":78,"available":77}
```

`length` is present only on successful **non-chunk** `encode`; `logical_length` is present only on successful chunk `encode`; neither is present on `decode` or `order`. `value_sha256` is present on successful `decode`, `order` and `encode`. For `encode`, digest the value decoded from its input; for `decode`, digest the returned current normalized value; for `order`, digest `{selected_index,bank}`. `length` is the exact byte-exact output size; exact-byte families compare emitted bytes against `encoded` in addition to this JSON. For `save.chunk`, `logical_length` is the complete uncompressed payload size and the `encoded` asset contains those **complete decompressed logical bytes**. Rust compares them with `decode_chunk_envelope(output).bytes`; compressed frame bytes and compressed output length are deliberately not compared with Go. Both implementations must additionally validate their own frame length bounds, declared logical size, checksum and round-trip fields. A Rust-produced compressed frame is a separate Go-decoded input case as described in node 4.3.

The Go producer accepts an error only when `errors.Is(err, storagedef.ErrCorrupt)` or `errors.Is(err, storagedef.ErrFutureVersion)` gives its class. Node 1.1 adds only `server/storage/storagedef` to the runtime-oracle **test-file** import whitelist in `packages/audit/dependency_test.go` and records the boundary in `packages/audit/AGENTS.md`; production runtime-oracle imports stay stdlib-only. Rust maps only `StorageError::Corrupt`/`FutureVersion` to those classes. For non-chunk writers, `OutputTooSmall` is derived from Go's successful encode length plus the requested `capacity`, then checked against Rust's exact `needed` and `available`; the destination must remain unchanged in writer tests. Chunk `OutputTooSmall` is checked only in node 4.2 against the Rust frame length. Error message text is excluded because it is not a cross-language format contract. Unexpected Go errors, panics, failed fixture reads and Rust harness errors fail the producer/test and never become `kind:"error"` assets.

`value_sha256` covers **every persisted or migration field**, including large collections, without placing a >256 KiB JSON value into one expected asset. Build a typed value tree from the exact fields below and hash its `StorageValueV1` encoding. It has these tags: null `0x00`; false `0x01`; true `0x02`; signed integer `0x03` followed by i64 LE; unsigned integer `0x04` followed by u64 LE; f32 `0x05` followed by raw IEEE-754 u32 LE bits; UTF-8 string `0x06` followed by u32 LE byte length and bytes; fixed byte string `0x07` followed by u32 LE length and bytes; array `0x08` followed by u32 LE count and child encodings; object `0x09` followed by u32 LE field count and each field as UTF-8 key length/u32 LE, key bytes, then child encoding, in ascending bytewise UTF-8 key order. Hash the complete tagged encoding with SHA-256. Arrays retain wire/DTO order; no sorting is allowed except the codec's documented canonical entity output. Map signed Go `int32/int64` and Rust `i32/i64` to signed tag, all unsigned integers to unsigned tag, and every stored f32 to raw-bit tag. UUID/identity fields are fixed 16-byte values, never formatted text in the tree. An absent optional location is null. Go and Rust independently construct the same typed tree from their own decoder outputs; neither may read the other's normalized value or substitute the input bytes/hash. Add a tiny independent cross-language golden tree with null, signed, unsigned, f32 negative zero, UTF-8, bytes, nested object and ordered array before any save case.

The fields in each nested object are the public Rust DTO names below; use the matching Go field even if its Go name differs. No undocumented field may be omitted. `ItemStack={item,count,durability}`; `Inventory={hotbar:{selected,slots[9]},backpack[27]}`; a location is `{dimension,position[3]}`; `ChunkKey` and `RegionKey` are `{dimension,x,z}`. Success trees are:

- Player: `{player_id,revision,display_name,current,yaw,pitch,safe,inventory,health,hunger,saturation_milli,exhaustion_milli,respawn_present,respawn_position[3],respawn_dimension,armor[4],needs_rewrite}`. An encode case hashes the **source input's decoded** `needs_rewrite` value, so a historical source may hash `true`; its newly encoded current output must separately decode with `needs_rewrite:false`.
- World metadata: `{format_version,seed,spawn_dimension,spawn_anchor:{x,z},world_time_ticks,day_phase_offset,weather_kind,weather_ticks_remaining,depths_spawn_anchor:{x,z},depths_seed_salt,difficulty}`. `weather_kind` is raw u8, including 7 and 255.
- Hostile: `{revision,records[]}`; each record has `{id,dimension,position[3],velocity[3],on_ground,yaw,health,attack_cooldown,hurt_cooldown,burn_cooldown,has_target,player_id,next_repath_ticks,distant_ticks,kind}`. V1 normalized kind is 0. No synthetic rewrite flag.
- Passive: `{revision,records[]}`; each record has `{id,dimension,position[3],velocity[3],on_ground,yaw,health}`.
- Chunk: `{key,revision,schema,chunk,migrated}` where `chunk={sections[24],drops[32],furnaces[32],chests[16]}`. A section has `{kind,bits,single,palette[],packed[]}`; drop `{generation,active,stack,block_index,age_ticks,pickup_delay_ticks}`; furnace `{generation,active,block_index,input,fuel,output,progress_ticks,burn_ticks}`; chest `{generation,active,block_index,items[27]}`. `schema` is the current normalized schema and `migrated` reflects historical repair.
- Companion: `{source_schema,revision,agent_namespace_id,records[],lifecycles[],queues[]}`. Body `{id,dimension,position[3],yaw,pitch,inventory}`; lifecycle `{id,active,memory_epoch,memory_revision,memory_operation_id,summary,tombstone_operation_id}`; queue `{id,has_current,current,pending[],summary}`; task `{command,plan_steps[],step_index,state,start_tick,deadline_ticks,fail_reason}`; plan step `{kind,x,y,z,block,player_id}`. Preserve legacy queue order, body owner IDs, FIFO order and raw v4 summary. The v1–v4 absence of namespace/lifecycle stays represented by decoded zeros/empty arrays; do not synthesize a valid v5 input.
- Region bank: `{generation,entries[1024]}` with each entry `{offset_sector,sector_count,payload_length,revision,payload_crc32c}`. Superblock decode/encode uses an empty object after successful validation; `order` uses `{selected_index,bank}` where index 0 means A and 1 means B.

For `encode`, the input's decoded value tree may carry historical rewrite flags; the expected digest comes from that decode, not from the current output's re-decoding. Every encode test also decodes its output and checks the current value fields, with documented rewrite/source-schema differences applied explicitly in its family packet. The per-family module verifies the whole digest and exact JSON equality through `assert_normalized`; a scalar or collection mutation in Go's expected digest must fail even if an unrelated round trip remains green.

## Candidate handoff and source identity

Each Go producer exports under one fresh absolute `RUNTIME_ORACLE_EXPORT_DIR` outside the repository. The child directory is created exclusively with a fixed producer ID: `runtime-oracle/storage-<family>`, `storage/metadata`, or `chunk/migration`; no producer writes tracked paths. Its `selection.json` contains exactly `producer_id`, `cases` (ordinary `CaseSpec` rows), `sources` (`SourceSpec` path and SHA-256 pairs) and `routes` (`ConsumerRoute` triples). Every case asset is placed beneath the child at the **same repository-relative path** named by its `AssetRef`, so the controller can verify hashes before create-exclusive copying into the tree. Source paths must be regular code/test/fixture files in the checkout and their hashes must match the current bytes; a newly created producer may still be untracked during export. Before the family commit, the controller stages precisely that reviewed producer path and verifies it will be tracked by the commit. The candidate root itself must be outside the realpath of the repo, free of symlink ancestors, and contain no file/path collision; all paths, lengths, IDs, route membership and hashes are validated before its first file is created. Existing `runner_helpers_test.go` export containment behavior is reused by the runtime-oracle producer.

The two package-local producers cannot call a helper from the `package main` test binary. Their own `_test.go` files implement the same small standalone guarded exporter: obtain repo root by walking to `go.work`; reject an unset/relative/export root under or symlinked into that root; reject non-regular/symlink ancestors and duplicate relative paths; precompute all case/source SHA-256 values and serialize the complete selection before creating a child with `os.Mkdir` (no `MkdirAll` through unknown ancestors); use `O_CREATE|O_EXCL` for every file; reload and verify bytes/hashes. `metadata_oracle_test.go` owns `storage/metadata`; `chunk_oracle_test.go` owns `chunk/migration`. Their tests also run with export unset and assert **zero writes**. The controller imports their `selection.json` with the same strict decoder and merge path used for runtime-oracle candidates; there is no cross-module Go import or production export.

`Discover` must include the new producer file paths in each affected family's `Family.Sources`: runtime-oracle `storage_<family>_test.go` for ordinary families, `metadata_oracle_test.go` for metadata, `chunk_oracle_test.go` and runtime-oracle `storage_chunk_test.go` for chunk, and `storage_region_test.go` for region. Add a source path only in its owning node after the file exists. The controller updates `discover.go`, matching manifest family source hashes/case IDs and registry together, without changing another family's sources. A candidate with a missing producer source path or stale hash fails; source fixtures are never rewritten. As in archived protocol completion, **preserve** the existing equal `source_revision` and `BaselineSourceRevision` during family-node commits; exact `Family.Sources` hashes bind every edited producer file. In node 5.1, after every producer and family manifest change is committed, capture that last family commit SHA, update both revision fields once, rerun all derived consumers and commit the closure. The ledger records both the captured source SHA and closure result SHA. Reconcile the manifest in memory and after reload.

The execution order for each corpus node is: (1) worker runs a Go producer to an external fresh child, hashes it and supplies its path; (2) controller reviews source and candidate, registers exact routes and source hashes, integrates assets/manifest by exclusive copies, then runs Go reconciliation; (3) worker or controller runs the Rust nonempty focused corpus against the integrated tree, fixes only that node's owned code, and reruns Go/Rust focused gates; (4) controller runs the listed derived manifest consumers and commits that family node. Before step 2 a Rust `-- --list` or compile check is allowed, but a zero-case focused run is expected to fail and is not reported as green. A failed integration is reverted by the controller to the previous manifest/asset commit without touching pre-existing user work.

For chunk's Rust-to-Go direction, the Rust context test writes one deterministic v9 frame to a separate fresh external child through `RUST_STORAGE_FRAME_EXPORT_DIR`, with create-exclusive and the same repository exclusion. The package-local Go `TestChunkMigrationOracle` reads only that reviewed frame path supplied by `RUST_STORAGE_FRAME_INPUT`, calls real `chunk.Decode` with the frozen key/revision, and exports its Go normalized result plus the frame as an ordinary `decode` candidate. No expected value is produced by the Rust encoder. The controller integrates this candidate only after Go decode succeeds, then the Rust corpus decodes the same frame. The Go-to-Rust direction is the normal Go-produced `decode` case. Neither side compares zstd block bytes.
